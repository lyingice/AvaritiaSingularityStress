# 原版（Create）机械动力合成器 —— 完整实现基线

> 目的：把 Create 机械合成器（Mechanical Crafter）的**全部功能实现、渲染实现、连接纹理系统与资源文件**完整固化下来，
> 作为我们自己「终焉动力合成器（ExtremeMechanicalCrafter）」重做时的**唯一复现依据**。
>
> 本文档只描述原版 Create 的行为，不描述我们当前的实现。末尾另附「复现时必须替换的硬编码点」与「验收清单」。
>
> 源码基线：`allapis/Create-mc1.21.1-dev`（Create mc1.21.1 dev 源码，纯 Java 原生）。
> 行号均相对该基线目录，可点击追溯。

## 0. 结论速览（先看这一段）

原版机械合成器由 **5 层**构成，缺一层都无法复现：

| 层 | 职责 | 关键类 |
|---|---|---|
| 方块层 | 状态（facing/pointing）、放置推导、扳手交互、目标方向 | `MechanicalCrafterBlock` |
| 方块实体层 | 1 格库存 + 连接组 + 阶段状态机 + 配方触发 | `MechanicalCrafterBlockEntity` |
| 连接层 | 扳手连接的建立/拆分/合并 + 组合库存排序 | `ConnectedInputHandler` / `CrafterHelper` |
| 配方链层 | 目标/前置遍历、网格聚合、配方匹配 | `RecipeGridHandler` / `MechanicalCraftingInput` / `MechanicalCraftingRecipe` |
| 外观层 | 静态模型 + CT 连接纹理 + 动态部件（齿轮/盖板/皮带/箭头/物品） | `MechanicalCrafterRenderer` / `CrafterCTBehaviour` / `CTModel` |

三个**最容易踩坑、必须理解**的事实：

1. **连接纹理 ≠ 相邻就连接**。CT 只认 `CrafterHelper.areCraftersConnected()`，
   也就是必须先用扳手加入同一个 `ConnectedInput` 控制组（`CrafterCTBehaviour.java:28`）。
2. **`pointing` 不参与静态模型**。blockstate 有 16 个变体，但模型只有 `facing` 的 Y 旋转；
   `pointing` 由渲染器对动态部件做绕 EAST 轴的 X 旋转（`MechanicalCrafterRenderer.java:213-221`）。
3. **父类静态方法不可被“覆盖”**。`MechanicalCrafterBlock.getTargetDirection(BlockState)`、
   `isValidTarget(...)`、`RecipeGridHandler.isCrafter(...)` 内部全部**硬编码** `AllBlocks.MECHANICAL_CRAFTER`。
   子类写同名静态方法只是“隐藏”，父类内部调用仍走原版。这是终焉合成器一切不一致的根源。

## 2. 注册链（复现时必须逐条对齐）

### 2.1 方块注册

`AllBlocks.java:1544-1556`：

```java
public static final BlockEntry<MechanicalCrafterBlock> MECHANICAL_CRAFTER =
    REGISTRATE.block("mechanical_crafter", MechanicalCrafterBlock::new)
        .initialProperties(SharedProperties::softMetal)
        .properties(p -> p.noOcclusion().mapColor(MapColor.TERRACOTTA_YELLOW))
        .transform(axeOrPickaxe())
        .blockstate(BlockStateGen.horizontalBlockProvider(true))   // 水平朝向 blockstate
        .transform(CStress.setImpact(2.0))                          // 应力影响 2.0
        .onRegister(CreateRegistrate.connectedTextures(CrafterCTBehaviour::new)) // CT 包装
        .addLayer(() -> RenderType::cutoutMipped)                   // 静态层
        .item()
        .transform(customItemModel())                               // 自定义物品模型
```

- CT 包装走 `CreateRegistrate.connectedTextures(...)`，不是 blockstate。

## 3. 方块层：`MechanicalCrafterBlock`

继承 `HorizontalKineticBlock`，实现 `IBE<MechanicalCrafterBlockEntity>` 与 `ICogWheel`。

### 3.1 状态

```java
public static final EnumProperty<Pointing> POINTING = EnumProperty.create("pointing", Pointing.class);
```

- 继承来的 `HORIZONTAL_FACING` 是**水平朝向 / 机械旋转轴**。
- 默认状态：`POINTING = Pointing.UP`（构造时 `registerDefaultState`）。
- `Pointing` 来自 catnip：`UP / DOWN / LEFT / RIGHT`，并提供 `getXRotation()` 与 `getCombinedDirection(Direction horizontal)`。

`createBlockStateDefinition`（`55-57`）：在父类定义基础上追加 `POINTING`。

`getRotationAxis`（`59-63`）：返回 `HORIZONTAL_FACING.getAxis()`，即机械轴就是水平朝向轴。

### 3.2 放置：`getStateForPlacement`（`66-86`）

```java
Direction face = context.getClickedFace();
BlockPos placedOnPos = context.getClickedPos().relative(face.getOpposite());
BlockState blockState = context.getLevel().getBlockState(placedOnPos);

if ((blockState.getBlock() != this) || (player != null && player.isShiftKeyDown())) {
    // 情形 A：不贴着同类方块放置，或玩家潜行 → 普通水平放置
    BlockState stateForPlacement = super.getStateForPlacement(context);
    Direction direction = stateForPlacement.getValue(HORIZONTAL_FACING);
    if (direction != face)
        stateForPlacement = stateForPlacement.setValue(POINTING, pointingFromFacing(face, direction));
    return stateForPlacement;
}

// 情形 B：贴着已有合成器放置 → 继承其 HORIZONTAL_FACING，形成同平面同朝向阵列
Direction otherFacing = blockState.getValue(HORIZONTAL_FACING);
Pointing pointing = pointingFromFacing(face, otherFacing);
return defaultBlockState().setValue(HORIZONTAL_FACING, otherFacing).setValue(POINTING, pointing);
```

语义：贴着已有合成器放置时，**自动同朝向**，这是搭出平面阵列的关键。

### 3.3 `pointingFromFacing(Direction pointingFace, Direction blockFacing)`（`129-142`）

```java
boolean positive = blockFacing.getAxisDirection() == AxisDirection.POSITIVE;
Pointing pointing = pointingFace == Direction.DOWN ? Pointing.UP : Pointing.DOWN;
if (pointingFace == Direction.EAST)  pointing = positive ? Pointing.LEFT  : Pointing.RIGHT;
if (pointingFace == Direction.WEST)  pointing = positive ? Pointing.RIGHT : Pointing.LEFT;
if (pointingFace == Direction.NORTH) pointing = positive ? Pointing.LEFT  : Pointing.RIGHT;
if (pointingFace == Direction.SOUTH) pointing = positive ? Pointing.RIGHT : Pointing.LEFT;
return pointing;
```

完整映射表（`positive` 表示 `blockFacing.getAxisDirection() == POSITIVE`）：

| 点击面 | blockFacing 正轴 | blockFacing 负轴 |
|---|---|---|
| DOWN | UP | UP |
| UP | DOWN | DOWN |
| EAST | LEFT | RIGHT |
| WEST | RIGHT | LEFT |
| NORTH | LEFT | RIGHT |
| SOUTH | RIGHT | LEFT |

### 3.4 拆除：`onRemove`（`89-127`）

三段逻辑：
1. **方向变化检测**：若 `state.getBlock() == newState.getBlock()` 且
   `getTargetDirection(state) != getTargetDirection(newState)` → 调用 `crafter.blockChanged()`
   （重建 `InvManipulationBehaviour`，刷新插入目标面）。
2. **BE 清理**（方块被替换时）：`covered` → 掉落 `CRAFTER_SLOT_COVER`；`!isMoving` → `ejectWholeGrid()`。
3. **断开连接**：遍历所有**与 facing 轴不同轴**的方向，若两侧 `ConnectedInput` 的 controller 坐标相同，
   调用 `ConnectedInputHandler.toggleConnection(...)` 拆分（避免留下指向已消失方块的连接）。

### 3.5 扳手：`onWrenched`（`145-154`）


### 3.6 交互：`useItemOn`（`157-230`）

判定用的 `hitResult.getDirection() == state.getValue(HORIZONTAL_FACING)`（正面）才处理，流程：

| 条件 | 行为 |
|---|---|
| 手持 `MECHANICAL_ARM` | 交还默认交互（不拦） |

### 3.9 目标方向：`getTargetDirection(BlockState)`（`250-259`）★★★

```java
public static Direction getTargetDirection(BlockState state) {
    if (!AllBlocks.MECHANICAL_CRAFTER.has(state))
        return Direction.UP;                      // ★ 硬编码：非原版方块一律返回 UP
    Direction facing = state.getValue(HORIZONTAL_FACING);
    Pointing point = state.getValue(POINTING);
    Vec3 targetVec = new Vec3(0, 1, 0);                              // 起点是 UP
    targetVec = VecHelper.rotate(targetVec, -point.getXRotation(), Axis.Z);   // 先绕 Z
    targetVec = VecHelper.rotate(targetVec, AngleHelper.horizontalAngle(facing), Axis.Y); // 再绕 Y
    return Direction.getNearest(targetVec.x, targetVec.y, targetVec.z);
}
```

结果特征：
- 输出只可能是 **UP / DOWN**，或与 `HORIZONTAL_FACING` 轴**垂直的左右方向**；
- **永远不会**指向 `HORIZONTAL_FACING` 轴的前/后。

### 4.2 内部类 `Inventory`（`59-88`）

```java
public Inventory(MechanicalCrafterBlockEntity blockEntity) {
    super(1, blockEntity, 1, false);   // slots=1, stackSize=1
    forbidExtraction();                // 外部不可抽出
    whenContentsChanged(slot -> {
        if (getItem(slot).isEmpty()) return;
        if (blockEntity.phase == Phase.IDLE) blockEntity.checkCompletedRecipe(false);
    });
}

@Override
public ItemStack insertItem(int slot, ItemStack stack, boolean simulate) {
    if (blockEntity.phase != Phase.IDLE) return stack;   // 非空闲拒收
    if (blockEntity.covered) return stack;               // 被盖住拒收
    ItemStack insertItem = super.insertItem(slot, stack, simulate);
    if (insertItem.getCount() != stack.getCount() && !simulate)
        level.playSound(null, pos, SoundEvents.ITEM_FRAME_ADD_ITEM, SoundSource.BLOCKS, .25f, .5f);
    return insertItem;
}
```

**两个关键参数**（对应 `SmartInventory(int slots, SyncedBlockEntity be, int stackSize, boolean stackNonStackables)`）：

- `slots = 1`：只有一格；
- `stackSize = 1`：**每格最多只放 1 个物品**，不是一整组。

`stackSize = 1` 是整条机械合成链能成立的前提——每格一物，才能把 N 个合成器的格子拼成一张配方网格。
`stackNonStackables = false` 表示不允许不可堆叠物品额外堆叠。

## 11. 物流集成：`CrafterUnpackingHandler`

`unpack(...)`（全文 79 行）：

1. 若包裹**没有**配方信息 → 走默认 unpack；
2. 取 `crafter.getInput()`，用 `input.getInventories(level, pos)` 拿到**按连接组排序的库存列表**；
3. 遍历「配方信息中的第 i 个物品」↔「排序后的第 i 个合成器库存」：
   - 目标槽已有物品 → 跳过；
   - 从包裹里找 `ItemStack.isSameItemSameComponents` 的物品，`copyWithCount(1)` 插入；
   - 每个合成器只放 1 个，成功后进入下一个；
4. 还有剩余物品 → 返回 `false`（失败）；
5. 非模拟 → `crafter.checkCompletedRecipe(true)`（**红石式启动**）。

复现要点：物流分发顺序**必须**和 `ConnectedInput.getInventories` 的排序一致，否则配方会错位。

## 15. 复现「终焉动力合成器」时必须替换的硬编码点

以下位置全部**写死了原版方块类型**，子类无法通过继承/静态隐藏改变行为。
这是当前终焉实现出现「纹理能连、功能链断裂」的根因。

| # | 位置 | 硬编码 | 影响 |
|---|---|---|---|
| 1 | `MechanicalCrafterBlock.getTargetDirection` | `if (!AllBlocks.MECHANICAL_CRAFTER.has(state)) return Direction.UP;` | 任何父类内部调用（`getTargetFace`/`onRemove`/`read` 粒子/渲染器）对终焉方块**一律返回 UP** |
| 2 | `MechanicalCrafterBlock.isValidTarget` | `AllBlocks.MECHANICAL_CRAFTER.has(targetState)` | 渲染器判断「皮带 vs 箭头」失效 |
| 3 | `ConnectedInputHandler.shouldConnect` | `AllBlocks.MECHANICAL_CRAFTER.has(neighbour)` | 终焉↔终焉无法建立连接（**已用 Mixin 打补丁**） |
| 4 | `RecipeGridHandler.isCrafter` | `return AllBlocks.MECHANICAL_CRAFTER.has(state);` | 终焉多方块链**完全不被识别**：目标/前置遍历失效 |
| 5 | `RecipeGridHandler.getTargetingCrafter` / `getPrecedingCrafters` | 直接调用 `MechanicalCrafterBlock.getTargetDirection(...)` | 即使修好 `isCrafter`，方向仍错 |
| 6 | `MechanicalCrafterBlockEntity.eject` | `AllBlocks.MECHANICAL_CRAFTER.has(blockState)` | 弹出位置退化到方块中心（不往前 0.75 格） |
| 7 | `CrafterHelper.getCrafter` | `instanceof MechanicalCrafterBlockEntity` | 子类**可用**（这是唯一的“天然兼容点”） |
| 8 | `AllBlockEntityTypes.MECHANICAL_CRAFTER` 的 `validBlocks` | 只含原版方块 | 自建 BE 需自行注册 |

**结论**：如果我们的目标是「完整复刻 + 支持 Avaritia 大型配方」，正确做法不是继续给这 8 处打补丁，
而是**自建一套并行的实现**（自有 Block / BlockEntity / ConnectionHandler / GridHandler / Renderer），
仅在**资源与视觉表现**上复用 Create 的模型与贴图思路。
