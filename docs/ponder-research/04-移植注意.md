## 1. 结论先行：**包名没有迁移，两版都已经是 net.createmod.ponder**

任务书里假设的「1.20.1 在 com.simibubi.ponder，1.21.1 迁到 net.createmod.ponder」**不成立**。

实证：

```bash
$ unzip -l "<Ponder-Forge-1.20.1-1.0.91.jar>" | grep -c 'com/simibubi/ponder'
0
$ unzip -l "<ponder-neoforge-1.0.82+mc1.21.1.jar>" | grep -c 'com/simibubi/ponder'
0
```

两个 jar 的顶层包根（`unzip -l | sed 's#/[^/]*$##' | sort -u`）对照：

```text

net/createmod/ponder/enums        net/createmod/ponder/enums
net/createmod/ponder/foundation   net/createmod/ponder/foundation
```

> **给手册的结论**：`com.simibubi.ponder` 这个包名在 **1.0.91 及以后就不存在了**。
> 真正的改名发生在更早的版本（Ponder 从 Create 拆成独立库时），**具体版本未验证**（本地没有更早的 jar）。
> 所以 1.20.1 ↔ 1.21.1 的移植**完全不用改 import** —— 这是最能省事的一条事实。

## 2. API 面差异：15 个核心接口逐个 `javap` 对比

对比方法：把两个 jar 的同一批类各自 `javap -public` 到文本文件，再 `diff`。

```bash
for c in api.scene.SceneBuilder api.scene.WorldInstructions api.scene.OverlayInstructions \
         api.scene.SelectionUtil api.scene.EffectInstructions api.scene.SpecialInstructions \
         api.registration.PonderPlugin api.registration.PonderSceneRegistrationHelper \
         api.registration.MultiSceneBuilder api.registration.StoryBoardEntry \
         api.registration.TagBuilder api.element.TextElementBuilder \
         api.element.InputElementBuilder api.element.ElementLink api.PonderPalette; do
   javap -cp "$J1" -public "net.createmod.ponder.$c" > /tmp/pd1/$c.txt
   javap -cp "$J2" -public "net.createmod.ponder.$c" > /tmp/pd2/$c.txt
   diff /tmp/pd1/$c.txt /tmp/pd2/$c.txt
done
```

**结果：14 个完全 SAME，唯一差异是 `WorldInstructions` 多了 1 个方法。**

```text

```

### 2.1 唯一 API 差异：`getHolderLookupProvider()`

**为什么加**：1.21 把 `ItemStack.save(CompoundTag)` 换成了需要 `HolderLookup.Provider` 的 `saveOptional(...)`，
于是 Ponder 必须把 provider 暴露给场景代码。Create 1.21.1 的两处真实用法（原文）：

```java
// ── 原文出处: allapis/Create-mc1.21.1-dev/src/main/java/com/simibubi/create/foundation/ponder/CreateSceneBuilder.java:242-246
		public void setFilterData(Selection selection, Class<? extends BlockEntity> teType, ItemStack filter) {
			modifyBlockEntityNBT(selection, teType, nbt -> {
				nbt.put("Filter", filter.saveOptional(world().getHolderLookupProvider()));
			});
		}
```

```java
// ── 原文出处: allapis/Create-mc1.21.1-dev/src/main/java/com/simibubi/create/foundation/ponder/CreateSceneBuilder.java:248-257
		public void instructArm(BlockPos armLocation, ArmBlockEntity.Phase phase, ItemStack heldItem,
								int targetedPoint) {
			modifyBlockEntityNBT(scene.getSceneBuildingUtil().select().position(armLocation), ArmBlockEntity.class,
				compound -> {
					NBTHelper.writeEnum(compound, "Phase", phase);
					compound.put("HeldItem", heldItem.saveOptional(world().getHolderLookupProvider()));
					compound.putInt("TargetPointIndex", targetedPoint);
					compound.putFloat("MovementProgress", 0);
				});
		}
```

> **1.20.1 的对应写法：未验证**。本地没有 Create 的 1.20.1 源码，不能凭印象写。
> 能确定的只有：`getHolderLookupProvider()` 这个**方法在 1.20.1 的 `WorldInstructions` 里不存在**（diff 已证明），
> 所以照着 1.21.1 的代码往 1.20.1 搬会编译失败。

**写法差异**（Forge → NeoForge 元数据的全部迁移）：

| 项 | Forge 1.20.1 | NeoForge 1.21.1 |
|---|---|---|
| 文件名 | `mods.toml` | **`neoforge.mods.toml`** |
| 依赖段 | `[[dependencies.ponder]]` | **`[[dependencies."ponder"]]`**（加引号） |
| 必需性 | `mandatory=true` | **`type="required"`** |
| 依赖 modId | `forge` | **`neoforge`** |
| mixin 段 | 无 | **`[[mixins]] config="..."`**（1.21 新增） |

> 两版都**硬依赖 Flywheel（`side = "CLIENT"`）** —— 这条从 1.20.1 到 1.21.1 没变。

## 6. lang / 本地化：**完全不变，中文可以直接搬**

两版关键常量逐一比对：

| 常量 | 1.20.1（1.0.91） | 1.21.1（1.0.82） | 结论 |
|---|---|---|---|
| `PonderLocalization.LANG_PREFIX` | `ponder.`（常量池 `#20 = Utf8 ponder.`） | `ponder.` | **相同** |
| `PonderScene.TITLE_KEY` | `ConstantValue: String header` | `ConstantValue: String header` | **相同** |
| 共享文本拼接模板 | `\u0001.ponder.shared.\u0001` | 同 | **相同** |
| 标签名模板 | `\u0001.ponder.tag.\u0001` | 同 | **相同** |
| 标签描述模板 | `\u0001.ponder.tag.\u0001.description` | 同 | **相同** |
| 场景文本模板 | `\u0001.ponder.\u0001.\u0001` | 同 | **相同** |

于是四种 key 形态在两版里完全相同：

```text
<ns>.ponder.<title第一参数>.header
<ns>.ponder.<title第一参数>.text_N
<ns>.ponder.tag.<tag路径>[.description]
<ns>.ponder.shared.<key>
```

> **实践含义**：你的 `zh_cn.json` 从 1.20.1 迁到 1.21.1 **一行都不用改**。

## 8. 明确标注为「未验证」的项

1. `com.simibubi.ponder` → `net.createmod.ponder` 的**具体迁移版本**（本地只有 1.0.91 / 1.0.82 两个 jar）。
2. 1.20.1 里「把 `ItemStack` 写进 NBT」的 **Create 实际写法**（没有 1.20.1 的 Create 源码）。

5. 版本号 `1.0.91`（1.20.1 线）与 `1.0.82`（1.21.1 线）看似"降级"，实为两条独立发布轨道各自递增 —— 这是观察到的现象，官方是否有意如此**未验证**。
