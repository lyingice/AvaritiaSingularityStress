### 1.2 还原出的命令树

```text
/ponder                                  → 打开索引首页（等价 /ponder tags 的实现路径，见下）
/ponder reload                           → PonderIndex.reload()
/ponder index                            → 索引界面
/ponder tags                             → 标签界面
/ponder <scene>                          → 播放某个组件的场景
/ponder <scene> <targets>                → 让指定玩家播放（requires 权限 2）
```

> **勘误（Lead 校对）**：上面字节码里的 `"scene"` / `"targets"` 是 **brigadier 的参数名**，
> 不是字面量子命令 —— `Commands.argument("scene", ResourceLocationArgument.id())`。
> 所以正确用法是 `/ponder mymod:my_machine`，**不是** `/ponder scene mymod:my_machine`。
> 游戏内 `/ponder ` 后的自动补全显示的是 `<scene>` 占位符，正是这个原因。

| 命令 | 作用 | 依据 |
|---|---|---|
| `/ponder` | 打开 Ponder 索引首页 | root `.executes(...)` → `openScene(..., index)` |
| `/ponder reload` | 重载 Ponder 索引 | → `reloadPonderIndex(player)` |
| `/ponder index` | 打开索引界面 | → `openScene("ponder:index", ...)` |
| `/ponder tags` | 打开标签界面 | → `openScene("ponder:tags", ...)` |
| `/ponder <id>` | 播放某个组件的场景（id 形如 `create:shaft`，是**组件id**不是剧本id） | → `openScene(argId, player)` |
| `/ponder <id> <players>` | 让指定玩家看某个场景（权限 2） | → `openScene(argId, players)` |

### 1.3 权限

```text
private static boolean lambda$register$0(CommandSourceStack);
   0: aload_0
   1: iconst_0
   2: invokevirtual #230  // CommandSourceStack.hasPermission:(I)Z
```

**根命令权限等级 = 0，即任何玩家都能用**。`scene <id> targets <players>` 上的 `.requires(...)` 是另一个谓词（`lambda$register$6`），其等级 Ponder 源码未说明，标注**未验证**。

`SimplePonderActions` 反编译调用链：

要点（对写手册极重要）：
1. **`openPonder` 用字符串分发**：`"index"`/`"ponder:index"` → `PonderIndexScreen`；`"ponder:tags"` → `PonderTagIndexScreen`；其他 → `PonderUI.of(id)`。
2. **id 不存在时只 `Logger.error`，不抛异常、不给玩家任何提示**（78 行）。所以「敲了 `/ponder xxx:yyy` 没反应」= id 拼错或根本没注册。
3. `reloadPonder` 只有一行：`PonderIndex.reload();`

### 1.5 客户端/服务端是怎么串起来的

`PonderClient.init()` 把两个"动作名"注册进 catnip 的简单动作包：

```text
  21: ldc  #51  // String openPonder
  28: invokestatic  ClientboundSimpleActionPacket.addAction(String, Supplier)
  31: ldc  #78  // String reloadPonder
  38: invokestatic  ClientboundSimpleActionPacket.addAction(String, Supplier)
```

即：**服务端执行 `/ponder` → 发包到客户端 → 客户端 `SimplePonderActions` 执行 UI 跳转**。
这解释一个常见误解：**`/ponder` 不是纯客户端命令**，它走"服务端指令 + 自定义包"。

## 2. 命令的注册挂载点

```text
> javap -cp "<jar>" -p 'net.createmod.ponder.NeoForgePonder$Events'
public class net.createmod.ponder.NeoForgePonder$Events {
  public static void registerCommands(net.neoforged.neoforge.event.RegisterCommandsEvent);
}
> 字节码：
   1: invokevirtual  RegisterCommandsEvent.getDispatcher()
   4: invokestatic   PonderCommands.register(CommandDispatcher)
   8: invokevirtual  RegisterCommandsEvent.getDispatcher()
  11: invokestatic   CatnipCommands.register(CommandDispatcher)
```

结论：**Ponder 是独立 mod（`modId = "ponder"`），自己在 `RegisterCommandsEvent` 上挂命令**。你的 mod **不需要**也**不应该**再注册 `/ponder`。

jar 内 `META-INF/neoforge.mods.toml` 关键行（原文）：

```toml
[[mods]]
modId = "ponder"
version = "1.0.82+mc1.21.1"
displayName = "Ponder"
description = '''Visual in-Game Documentation'''

[[dependencies."ponder"]]
modId = "neoforge"
type="required"
versionRange = "[21.1.206,)"
side = "BOTH"

[[dependencies."ponder"]]
modId = "minecraft"
type="required"
versionRange = "[1.21.1]"

[[dependencies."ponder"]]
modId = "flywheel"
type="required"
versionRange = "[1.0.0,2.0)"
ordering = "AFTER"
side = "CLIENT"
```

> ⚠️ **Ponder 硬依赖 Flywheel（`side = "CLIENT"`）**。只装 Ponder 不装 Flywheel 客户端必崩。要写进手册"环境准备"。

### 3.5 关于 `ClientModInitializer`：**NeoForge 没有这个概念**

任务书里提到「DistExecutor / @OnlyIn / ClientModInitializer」三种手段。前两个在 Create 里都有实例，
第三个 `ClientModInitializer` 是 **Fabric** 的入口接口，**Forge / NeoForge 侧不存在**。

对应的三个平台概念对照（本仓库只覆盖 NeoForge 一列，是有源码证据的）：

| Fabric | NeoForge / Forge | Create 1.21.1 的做法 |
|---|---|---|
| `ClientModInitializer` | **无**。客户端入口靠 `@Mod(...)` 类的 `dist` 参数 | `@Mod(value = Create.ID, dist = Dist.CLIENT)` |
| `ModInitializer` | `@Mod` 类构造器 + `IEventBus.addListener` | `public CreateClient(IEventBus modEventBus) { onCtorClient(modEventBus); }` |
| `ClientModInitializer.onInitializeClient` | **`FMLClientSetupEvent`** | `modEventBus.addListener(CreateClient::clientInit);` |
| Fabric `EnvType.CLIENT` 标注 | **`@OnlyIn(Dist.CLIENT)`** | Create 全树 **311 处** |

> **给手册的结论**：如果读者是从 Fabric 教程过来的，要把 `ClientModInitializer` 换成
> 「`@Mod(dist = Dist.CLIENT)` + `FMLClientSetupEvent`」。这是最容易误导人的一处跨平台差异。

## 4. Create 主动规避的运行期问题（每条有源码证据）

### 4.1 问题：Ponder 世界重建后，多方块控制器的坐标全错

**症状**：大传送带 / 多格方块实体在 Ponder 里不同步、控制端丢失。
**Create 的解法**：`PonderPlugin.onPonderLevelRestore` 里重算。

```java
// ── 原文出处: allapis/Create-mc1.21.1-dev/src/main/java/com/simibubi/create/foundation/ponder/CreatePonderPlugin.java:49-52
	@Override
	public void onPonderLevelRestore(PonderLevel ponderLevel) {
		PonderWorldBlockEntityFix.fixControllerBlockEntities(ponderLevel);
	}
```

```java
// ── 原文出处: allapis/Create-mc1.21.1-dev/src/main/java/com/simibubi/create/foundation/ponder/PonderWorldBlockEntityFix.java:11-44
public class PonderWorldBlockEntityFix {

	public static void fixControllerBlockEntities(PonderLevel world) {
		for (BlockEntity blockEntity : world.getBlockEntities()) {

			if (blockEntity instanceof BeltBlockEntity beltBlockEntity) {
				if (!beltBlockEntity.isController())
					continue;
				BlockPos controllerPos = blockEntity.getBlockPos();
				for (BlockPos blockPos : BeltBlock.getBeltChain(world, controllerPos)) {
					BlockEntity blockEntity2 = world.getBlockEntity(blockPos);
					if (!(blockEntity2 instanceof BeltBlockEntity belt2))
						continue;
					belt2.setController(controllerPos);
				}
			}

			if (blockEntity instanceof IMultiBlockEntityContainer multiBlockEntity) {
				BlockPos lastKnown = multiBlockEntity.getLastKnownPos();
				BlockPos current = blockEntity.getBlockPos();
				if (lastKnown == null || current == null)
					continue;
				if (multiBlockEntity.isController())
					continue;
				if (!lastKnown.equals(current)) {
					BlockPos newControllerPos = multiBlockEntity.getController().offset(current.subtract(lastKnown));
					multiBlockEntity.setController(newControllerPos);
				}
			}

		}
	}

}
```

> 机制：`PonderLevel` 是从 nbt 复制出来的独立世界（`PonderLevel extends SchematicLevel`，javap 实证）。`getLastKnownPos()` 与当前 `getBlockPos()` 的差值必须补到 controller 坐标上，否则 `setController` 指向虚空。
>
> **你的 mod 有自研多方块/主从方块时，必须实现 `onPonderLevelRestore`** —— 这是 Ponder 官方留的唯一钩子。

```java
// ── 原文出处: allapis/Create-mc1.21.1-dev/src/main/java/com/simibubi/create/foundation/ponder/CreateSceneBuilder.java:324-329
		private void markSmartBlockEntityVirtual(Selection selection) {
```

## 5. 排错清单（症状 → 原因 → 验证）

| # | 症状 | 最可能原因 | 怎么验证 |
|---|---|---|---|
| 1 | 服务器启动 `NoClassDefFoundError: net/minecraft/client/...` | 注册入口类没加 `dist = Dist.CLIENT` | 看崩溃栈里的类名是不是你的 plugin / 场景类 |
| 2 | 游戏里完全没有 Ponder 提示 | `PonderIndex.addPlugin` 没被调用，或不在 `FMLClientSetupEvent` 里 | 用 `PonderIndex.streamPlugins()` 打日志数插件个数 |
| 3 | `/ponder mod:xxx` 无反应也无报错 | id 拼错或没注册（`SimplePonderActions` 只 `Logger.error`） | 看 `logs/latest.log` 的 Error 行；或 `/ponder index` 看图标在不在 |
| 4 | 场景能开，但只有底板、没有方块 | `.nbt` 路径不对：`assets/<modid>/ponder/<scene id>.nbt` | 打开 jar 核对路径，注意必须全小写 |
| 5 | 文字显示成原始 key | 语言文件 key 写错（写成 `.title` 而非 `.header`）或 `text_N` 错位 | 对照 `01` §7 的四种 key 形态 |
| 6 | `runData` 生成的 lang 里没有 ponder key | 忘了在 datagen 里再 `addPlugin` 一次 | 见 §4.3 |
| 7 | 独立区块绕世界原点乱转 | 没先 `configureCenterOfRotation` | 检查 `rotateSection` 前一行 |
| 8 | 红石演示"通不了电" | `toggleRedstonePower` 是**翻转**，调用奇数次导致状态反了 | 数调用次数是否成对 |
| 9 | 关键帧落在动画中段 | `addLazyKeyframe()` 的 lazy 语义 | 换 `addKeyframe()` 或前后补 `idle` |
| 10 | 客户端崩溃提到 `flywheel` | 只装 Ponder 没装 Flywheel | 见 §2 的 mods.toml |
| 11 | 改方块后机器不响应 | 方块实体没标脏 | 见 §4.2 |
| 12 | 多方块结构在 Ponder 里坐标错 | 没实现 `onPonderLevelRestore` | 见 §4.1 |

### 5.1 一条万能排查顺序

```text
/ponder reload          ① 索引重载
/ponder index           ② 看你的标签/组件在不在索引里
/ponder tags            ③ 看标签注册成功没
/ponder <你的id>        ④ 看场景能不能编译出来（注意没有 scene 这个字面量子命令）
```

四个命令按顺序敲，能定位到"注册 / 索引 / 标签 / 场景"四层中坏在哪一层。

## 7. `PonderIndex.editingModeActive()` 与"编辑模式"

签名：`public static boolean editingModeActive()`

反编译证据（`PonderLocalization.getShared` / `getSpecific` 开头都会先问它）：

```text
public java.lang.String getShared(ResourceLocation);
   0: invokestatic  PonderIndex.editingModeActive:()Z
   3: ifeq  45
   6: ...  // 编辑模式下直接返回内存里的注册原文，而不是 I18n 翻译
```

**含义**：编辑模式下 Ponder 显示你写在代码里的英文原文（而非 lang 文件里的值），方便对照。具体开关方式由 Ponder 的配置/按键控制，Create 源码里 0 处引用，**未验证**。

## 8. 本次实证：炽骨立方机壳场景（2026-11-06）

这一节全部是**本仓库亲手跑出来**的，不是文档抄写。场景文件见
`src/main/java/committee/nova/avaritia_singularity_stress/ponder/`。

### 8.1 `.nbt` 可以脚本生成，不必进游戏用结构方块

Ponder 读的是原版 `StructureTemplate`（`PonderSceneRegistry.loadSchematic` 返回该类型），
1.20.5+ 的 NBT 结构是：

```text
{ DataVersion:int, size:[I;x,y,z],
  palette:[{Name:"ns:block", Properties:{axis:"x"}}],
  blocks:[{pos:[I;x,y,z], state:int}], entities:[] }
```

`tools/gen_ponder_schematic.py` 直接写这个格式 + gzip，实测被游戏正常加载
（日志无 `Ponder schematic missing`，方块按预期出现）。**结论：可复现、可版本管理，推荐。**

### 8.2 孤立的传动方块不转，也不会画

第一次实现时每个演示位只有一格轴/齿轮，`setKineticSpeed(单格, 32)` 之后画面仍是死方块。
改成**连成一排**（轴-轴-轴-齿轮-轴-轴）后立刻正常。
推测是 Create 的 kinetic visual 需要方块构成网络才更新；**未逐行验证源码，但实测有效**。

### 8.3 `setBlocks` 换方块后必须重给转速

```java
scene.world().setBlocks(pos, encasedState, true);
scene.world().setKineticSpeed(powerLine, 32);   // ← 少了这句，被替换的那一格当场停转
```

原因：新方块实体是新建的，`speed` 为 0；`setBlocks` 不会继承旧 BE 的速度。
Create 原版 `KineticsScenes.shaftsCanBeEncased` 的字节码里，每次 `setBlocks` 后都紧跟一次
`setKineticSpeed(shaftLine, 32.0f)`，与此一致。

### 8.4 包壳点不要相邻

两个包壳方块紧挨着（x=1 与 x=2）时，视觉上糊成一个 2 格宽的方块，看不出是两种东西。
Create 原版把两个包壳点放在 x=1 和 x=3（隔一格），本仓库沿用该间隔。

### 8.5 Ponder 不跑 Flywheel visual → 包壳方块只剩外壳（已定位，已修）

实测现象（游戏内截图对比）：

| 环境 | 炽骨立方齿轮箱 |
| --- | --- |
| 游戏世界（正常游玩） | 齿轮**齿盘可见**（白色齿轮围在机壳外） |
| Ponder 场景内 | 只剩机壳外壳，齿轮看不见 |

**根因（证据链）**：

1. `net.createmod.ponder` jar 里 **0 处 `VisualizationManager`** → Flywheel 的 visual 系统
   只挂在 `ClientLevel` 上，Ponder 的假世界 `PonderLevel` 拿不到，visual 整个不参与。
2. 同一 jar 里 **`WorldSectionElementImpl` 引用了 `BlockEntityRenderDispatcher`**
   → Ponder 渲染方块实体走的是 **BER**，不是 visual。
3. Ponder 画方块本体走 `VirtualRenderHelper.blockModel(BlockState)` + catnip 的
   `BakedModelBuffererImpl`，即只画 **baked model**。
4. Create 的 `assets/create/models/block/encased_cogwheel/block.json` 拆开只有 4 个 element
   （下半 / 中间层 / 中间层内缩副 / 上半），**一条齿也没有**；齿由
   `EncasedCogVisual`（Flywheel）现画。`create` jar 里也**不存在 `CogwheelRenderer`**
   （只有 `KineticBlockEntityRenderer` 与 `ShaftRenderer`）。

**推论**：Create 官方 `/ponder create:cogwheel_casing` 里，包壳后同样看不到齿。
这不是本仓库的注册错误。

**修法（已落地）**：`PonderKineticFallbackRenderer`（`init/client/renderer/`），
在 `EntityRenderersEvent.RegisterRenderers` 里给 3 个包壳 BE 挂上，渲染对应**普通方块**的模型
（`AllBlocks.SHAFT` / `COGWHEEL` / `LARGE_COGWHEEL`），并且：

```java
if (be.getLevel() instanceof ClientLevel) {
    return;   // 游戏内交给 visual，避免画两遍
}
```

齿能露出来是因为普通齿轮模型的齿本来就伸出方块边界：小齿轮 `[-1,6.5,6.5]→[17,9.5,9.5]`，
大齿轮 `[-7,6.525,6.5]→[23,9.475,9.5]`；而包壳外壳只有 0..16。

**Ponder 里画出来的是静态齿**（不转）——场景本来就没有真正的动能模拟。

**顺带修真 bug**：`blaze_cube_encased_shaft.json` 的 `opening` 槽位原先填了外壳纹理，
等于把轴孔糊死。官方安山填 `create:block/gearbox`、黄铜填 `create:block/brass_gearbox`，
本仓库改用 `create:block/brass_gearbox`（黄铜色最接近炽骨立方的金橙）。

### 8.7 【工具限制】合成键盘事件送不进 Minecraft 窗口

自动化验证时踩到：`SetForegroundWindow` 返回 true 但前台随即被别的窗口（DSH/QQ）抢回，
`keybd_event` / SendKeys 发出的 `T`、`F3` 均无反应（画面上连 F3 调试信息都不出）。
`PrintWindow` 抓图不需要焦点，所以**截图可行、输入不可行**。
结论：Ponder 场景的实机验证要么人工操作，要么在 mod 里加临时触发钩子，别指望脚本按键。
