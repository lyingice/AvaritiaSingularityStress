## 0. 一句话定义

> 一台**装在传送带上、可跨远距离配对**的隧道：物品随带子流进「入口端」后不再出现，而是在同频道的「出口端」按玩家事先选定的**那个面**流出去，落到相邻的传送带 / 漏斗 / 容器上（或从带子尽头弹出去）。

它和黄铜隧道的差别只有两条，但这两条决定整个实现：

| | 黄铜隧道（Create） | 空间折跃隧道（本设计） |
| --- | --- | --- |
| 出口在哪 | 紧邻的左右两侧 | **远端的另一台同频道隧道**，位置由配对决定 |
| 出口方向怎么定 | 自动（SelectionMode 在多个有效侧里挑） | **玩家显式选定的一个面**（需求原文） |

### 不做的事（第一版边界）

- ❌ **跨维度**：无线表按维度分区（`WirelessNetwork.CONNECTIONS` 是 `IdentityHashMap<LevelAccessor, …>`），跨维度要改底层，不在本版。
- ❌ 多路分拣（黄铜隧道的 SPLIT / ROUND_ROBIN / SYNCHRONIZE 那 7 种模式）：本版**只做单一指定方向**。
- ❌ 双向同时传：本版是「入口端 → 出口端」单向。
- ❌ 自绘模型/贴图：**按你立的规则，先复制 Create 黄铜隧道贴图占位**（见 §12），你后期人工改。

## 2. 玩家体验流程（本轮最重要的一节）

```text
① 放置：放在一条水平传送带上（与放黄铜隧道完全一样）
       ↓  默认是「入口端」，并记下放置者为频道所有者
② 扳手右键：切换角色  入口端 ⇄ 出口端（动作条提示）
       ↓
③ 空手右键：打开无线频率界面（复用 B9/B10 那套），设 0~9999 频率 + 私有/公用
       ↓  两端同频率；私有频道要求同一玩家
④ 出口端上「扳手 + 潜行右键」：循环切换输出面 北 → 东 → 南 → 西 → 北 …
       ↓  选中的面常亮一个箭头标记（见 §6.4）
⑤ 物品随带子进入口端 → 消失 → 从出口端选定面流出
```

**三条体验承诺**（写进验收标准）：

1. 玩家**不需要**站在两端之间，也不需要视线通畅——折跃本来就是无空间的。
2. 出口方向**确定**：同一方向下物品永远从同一个面流出（不像黄铜隧道会轮询），玩家才能规划物流。
3. 任何"传不过去"的情况，物品**不消失、不复制**：停在入口端缓存，带子被堵（背压），并给出明确状态文案。

## 3. 方块实现（继承谁、为什么）

### 3.1 继承链

```text
Block
└── BeltTunnelBlock        (Create：贴带、HORIZONTAL_AXIS、SHAPE 形状推断、扳手切窗口)
    └── BrassTunnelBlock   (Create：几乎只是"把缓存物品还给你"的右键)
        └── WarpTunnelBlock   ← 我们写
```

**为什么必须继承到 `BrassTunnelBlock` 这一层**（两处硬检查决定的）：

| 检查点 | 代码位置 | 后果 |
| --- | --- | --- |
| 物品拦截：`nextTunnel instanceof BrassTunnelBlockEntity` | `BeltTunnelInteractionHandler:52` | BE 不继承黄铜隧道 BE，**带上的物品永远不会被拦截**，本机等于装饰 |
| 停滞判定：`getBlockState(pos).getBlock() instanceof BrassTunnelBlock` | `BeltTunnelInteractionHandler:123` | 方块不继承黄铜隧道方块，带子**不会在它前面停下**，物品直接穿过去 |

两条都是 Create 里写死的 `instanceof`。想复用"隧道拦截 + 停滞"，就必须走这条继承链；
换别的做法只能 mixin 进 Create 的传送带 tick——本模组虽有 4 个 mixin，但都在流体/应力侧，不建议为这个再开。

### 3.2 方块状态

| 属性 | 类型 | 语义 |
| --- | --- | --- |
| `HORIZONTAL_AXIS` | `Direction.Axis`（继承） | 底下带子的水平轴 |
| `SHAPE` | 枚举（继承） | 只允许 STRAIGHT / WINDOW / CLOSED（T/CROSS 不做） |
| **`EXPORTING`** | `BooleanProperty`（新增） | `false`=入口端（默认）；`true`=出口端 |
| **`OUTPUT`** | `EnumProperty<Direction>`（新增，4 水平值） | 仅出口端有意义：物品从哪个面流出 |
| **`POWERED`** | `BooleanProperty`（新增，可选） | 红石通电即停（待拍板，§14 第 4 条） |

默认：`SHAPE=STRAIGHT, EXPORTING=false, OUTPUT=NORTH, POWERED=false`。

### 3.3 放置与存活

- `canSurvive`：继承（必须放在水平带子 `CASING=true` 的段上）。
- `setPlacedBy`：写 `owner`（照抄 `WirelessItemFunnelBlock.setPlacedBy`）。
- `neighborChanged`：下方带子没了 → 掉落自身（继承）。

### 3.4 交互总表（三条交互会打架，顺序必须按真实规则设计）

| 手上的东西 | 行为 | 实现要点 |
| --- | --- | --- |
| 空手右键 | 打开无线频率界面（`WirelessConfigMenu`） | 两端都要能设频率 |
| 扳手右键 | **切换角色**：入口端 ⇄ 出口端 | 走 `IWrenchable.onWrenched`（Create 扳手会调它） |
| 扳手 + 潜行右键 | **循环输出面**（仅出口端生效） | 同上，潜行分支 |
| 频率卡右键 | 写入频率 | `useWithoutItem` 在手持卡/扳手时 **PASS 让位**（复用 `WirelessBlockInteractions.deferToHeldItem`） |
| 其他物品 | 放行 | 不要吃点击 |

> ⚠️ `BrassTunnelBlock.useWithoutItem` 原本是"把缓存物品还给你"，必须覆写掉，否则空手右键会被塞一堆物品而不是开界面。

## 4. 角色与配对

### 4.1 两端角色

| 角色 | `EXPORTING` | 职责 | 缓存 |
| --- | --- | --- | --- |
| 入口端 | `false` | 从带子上吃下整堆，放进自己缓存，**等出口端来取** | 1 堆（≤64） |
| 出口端 | `true` | 每 5 tick 向对端要货，按 `OUTPUT` 方向注入目标 | 无 |

**为什么是"出口端拉"而不是"入口端推"**：照抄本模组 B9 无线漏斗已验证结构
（`extractIntoCache` / `injectFromPeer`），物品永远只存在于一端，不会出现"两边各半份"的对账问题。

### 4.2 配对规则（复用现有底层）

| 规则 | 来源 | 说明 |
| --- | --- | --- |
| 频道 = 频率 + 可见性 + owner | `WirelessKey` | 私有只与同 owner 配对；公私不混 |
| 同维度才配对 | `WirelessNetwork` 按维度分表 | 跨维度不支持 |
| **一对一半径内解析** | `WirelessService.findPeer(self, range)` | 0 台或 ≥2 台都返回 null |
| 距离上限 | 新增 `warpTunnelRange`，默认 **128**，范围 1–4096 | 见 §14 第 3 条 |

### 4.3 类型校验（新增约束，必须写死）

`findPeer` 返回 `WirelessDevice`，**可能是同频的 B9 漏斗或 B10 应力桥**。所以解析后必须：

```text
peer instanceof WarpTunnelBlockEntity  且  peer.EXPORTING == true 且  self.EXPORTING == false
```

不满足 → 状态 `bad_peer`，不搬运。

> 为什么必须落到代码里：`getStackToDistribute()` 是 public 的，谁都能读。
> 不校验类型，玩家把隧道和漏斗设同频就会出现"漏斗从隧道缓存里偷物品"的串味。

### 4.4 同角色配对

入口端只认出口端，出口端只认入口端；两边都是入口端（或都是出口端）→ 各自显示 `no_peer`，
不报错、不吞物品（缓存满后带子自然停）。

## 5. 物品流转时序（可直接照写）

每 **5 tick**（沿用 `WirelessLifecycle.TICK_INTERVAL`，不新开 tick 源）：

```text
【出口端】
1. POWERED 或无频率 → return
2. peer = findPeer(self, warpTunnelRange)
   类型不符 / 不是入口端 → 状态=bad_peer，return
3. !level.isLoaded(peer.pos) → 状态=peer_unloaded，return
4. stack = peer.getStackToDistribute()；空 → 状态=idle，return
5. batch = min(stack.count, BATCH)            // BATCH 见 §14 第 6 条，建议 16
6. target = resolveExit(OUTPUT)               // §6.2；无效 → 状态=exit_blocked，return
7. 模拟注入 → accepted；accepted==0 → 状态=exit_blocked，return
8. 真注入 accepted；从 peer 缓存扣 accepted
   执行时失败 → 没进去的退回 peer 缓存（照抄 B9「绝不凭空消失」）
9. peer.setStackToDistribute(剩余)（内部自动 setChanged + sendData）
   剩余为空 → 两端各播一次折跃粒子/音效

【入口端】
1. POWERED → return
2. 缓存非空 → 什么也不做（等出口端拉）
3. 缓存为空 → 由 Create 隧道拦截机制自动灌入（我们只提供 canTakeItems()=true）
```

### 5.1 背压与停滞（别把带子卡死又说不清）

Create 的拦截逻辑（`BeltTunnelInteractionHandler:41-44` 与 `:123`）在 `canTakeItems()` 为 false 时会让
**带上的物品停在隧道前一格**。我们沿用：

| 状态 | `canTakeItems()` | 带子表现 |
| --- | --- | --- |
| 缓存空 | `true` | 物品被吸进去 |
| 缓存有货（出口端没在取） | `false` | 物品**停在隧道前**，视觉上堵住 |
| 未配对 / 无频率 | `false` | 同上（玩家立刻发现配错） |

> **不要**做成"没配对就把物品吞掉"——那是数据丢失。

### 5.2 保序与吞吐

- 单一方向 + 单一对端 → 天然 FIFO（缓存 1 堆）。
- 吞吐上限 = `BATCH / 5 tick`；BATCH=16 → ≈64 件/秒，远超满速带子。
- 缓存只 1 堆 → 换品类要等前面的取空（B9 同款语义）。

## 6. 出口方向：玩家选择怎么落地（需求核心）

### 6.1 选择方式

| 方案 | 手感 | 成本 | 结论 |
| --- | --- | --- | --- |
| **扳手 + 潜行右键循环 4 面** | 与 Create 全家族一致，零 GUI | 低 | ✅ 推荐（默认） |
| 扳手右键循环（不潜行） | 与"切角色"冲突 | — | ❌ |
| 出口端 GUI 点箭头 | 直观但要新 Screen + 包 | 中 | 备选（后续可加，不动数据结构） |

结果存 `OUTPUT` 方块状态 → 天然进存档、天然同步、天然被 Jade 读到，**不需要额外 NBT**。

### 6.2 出口解析（以出口端 `P`、脚下带子 `B` 为准）

```text
1) Q = P.below().relative(face)
   若 Q 上有 DirectBeltInputBehaviour 且 canInsertFromSide(face)  → (A) 侧向插入
2) 否则若 face == B.getMovementFacing() 且 Q 方向无实心方块阻挡   → (B) 带尾抛 ItemEntity
3) 否则若 Q 上有 IItemHandler 容器                               → (C) 塞进容器
   否则                                                          → 无效
```

| 路径 | 用什么 API | 备注 |
| --- | --- | --- |
| (A) 侧向插入 | `DirectBeltInputBehaviour.handleInsertion(stack, face, simulate)` | 与黄铜隧道 `insertIntoTunnel:398-405` 同一条路 |
| (B) 带尾抛出 | `new ItemEntity` + 初速（照抄 `:415-431`） | 表现"从带子尽头飞出去" |
| (C) 塞容器 | `ItemHandlerHelper.insertItemStacked` | 让"直接进箱子"成立；先模拟后提交 |

> 只认这 3 条。不做"面朝什么都能塞"的宽松匹配，否则玩家选错方向时毫无反馈。

### 6.3 无效出口

物品留在入口端缓存，带子堵住，状态 `exit_blocked`；出口端选定面显示**红色箭头**。

### 6.4 方向可视化（低成本版）

| 表现 | 做法 | 分期 |
| --- | --- | --- |
| 选中面常亮箭头 | 复用继承来的 flap：`flap(OUTPUT, false)` 保持 | 第一版 |
| 传送瞬间粒子 | 两端各撒 8–12 粒 `ParticleTypes.PORTAL` | 第一版 |
| 传送音效 | `SoundEvents.ENDERMAN_TELEPORT`（0.4 音量，两端各一次） | 第一版 |
| 环状折跃门模型 + 自定义渲染 | 需自写 model/renderer | 第二版（等你的贴图改造） |

### 7.2 同步策略

- 方块状态：自动同步。
- 缓存内容：继承的 `sendData()` 已同步（黄铜隧道护目镜信息就靠它）。
- 状态文案：服务端算好写进 NBT，客户端只翻译，**不重复判定逻辑**。

### 7.3 Jade / 护目镜

| 行 | 内容 |
| --- | --- |
| 1 | 空间折跃隧道 · 入口端 / 出口端 |

| 3 | 对端：已配对 / 未找到 / 冲突（2 台）/ 类型不符 / 未加载 |

## 8. 边界与异常清单（每条都要有确定行为）

| # | 情况 | 行为 | 物品安全 |
| --- | --- | --- | --- |
| 1 | 无频率 | 不搬，`status.unbound` | 缓存保留 |
| 2 | 频道内 0 台对端 | 不搬，`status.no_peer` | 缓存保留 |
| 3 | 频道内 ≥2 台对端 | 不搬，`status.ambiguous` | 缓存保留 |
| 4 | 对端不是本方块 / 角色不互补 | 不搬，`status.bad_peer` | 缓存保留 |
| 5 | 对端区块未加载 | 不搬，`status.peer_unloaded` | 缓存保留 |
| 6 | 出口面无效 / 被堵 | 不搬，`status.exit_blocked`，箭头变红 | 缓存保留 |
| 7 | 注入瞬间目标消失（竞态） | 退回缓存，本次作废 | 不丢不复制 |
| 8 | 隧道被破坏 | `destroy()` 里 `popResource` 掉缓存 | 掉落物返还 |
| 9 | 下方带子消失 | 继承：方块掉落 | 同上 |
| 10 | 带子反向 / 停转 | 入口端不吃（Create 不会送进来）；出口端仍可注入 | — |
| 11 | 两头同角色 | 各报 `no_peer` | — |
| 12 | 出口面指向自己脚下同一格 | 视为有效（等价"原地吐出"），不做特殊限制 | — |
| 13 | 区块卸载瞬间 | `invalidate()` 注销频道 → 对端显示 `peer_unloaded` | — |
| 14 | 服务器重启 | 缓存随 NBT 恢复 | — |

## 9. 性能预算

| 项 | 预算 | 理由 |
| --- | --- | --- |
| tick 来源 | 复用 `WirelessLifecycle` 的 5 tick | 不新增 ServerTick 监听器 |
| 每 5 tick 每台的工作 | 1 次 `findPeer`（频道表通常 1–3 条）+ 1 次能力查询 + 1 次模拟注入 | 常数级 |
| 频道表遍历 | `WirelessNetwork.peers` 返回拷贝快照 | 无锁、无并发修改 |
| 渲染 | 第一版无自定义 renderer | 只有 flap + 偶发粒子 |
| 大基地风险 | 同频 >2 台直接停机报冲突 | 避免"多人共用频率时每台扫全频道" |

## 10. 实现风险与取舍（要写进代码注释）

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **依赖 Create 内部实现** | 继承 `BrassTunnelBlockEntity` 并覆写 `hasDistributionBehaviour()` / `canTakeItems()` / `tick()`；Create 大版本升级可能改这些 | `gradle.properties` 已钉 `create_version=6.0.10-280`；覆写面控制在这 4 个方法；升级时按 §13 回归 |
| **package-private 字段不可访问** | `stackToDistribute` / `distributionProgress` / `filtering` 都没修饰符（同包可见），我们读不到 | 只走 public 的 `getStackToDistribute()` / `setStackToDistribute(…)`；`filtering` 用覆写 `createSidedFilter()` 注入，不碰字段 |
| **父类 `read()` 会调 `filtering.updateFilterPresence()`** | 不给 `filtering` 赋值就 NPE | 必须提供 `SidedFilteringBehaviour`，不能换成普通 `FilteringBehaviour` |
| **父类 `addBehaviours` 会塞 SelectionMode 滚轮** | 本方块没有多输出，不该出现 | 覆写 `addBehaviours` 只留过滤槽 |
| **父类 `useWithoutItem` 会返还缓存** | 与"空手开界面"冲突 | 方块层覆写 |
| **`instanceof` 收口在 Create 侧** | 不继承就拿不到"带子停滞" | 已选继承方案（§3.1），接受版本绑定 |
