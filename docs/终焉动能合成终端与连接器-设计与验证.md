# B29 终焉动能合成终端 / B30 终焉连接器

自动合成系统：终端选择配方后，从相邻仓库调集材料，按配方格自动投入经连接器组网的终焉合成器槽位，由合成器网络自行合成。

> 默认决策（用户未指定时的取舍）：**仓库 = 终端相邻容器**（经 ItemHandler 抽取，无额外依赖）；**分阶段交付**，第一阶段为核心自动合成闭环 + 基础 GUI。

## B30 终焉连接器 `extreme_connector`

- CT 方块（`DirectionalBlock`），贴在终焉动能合成器的**背面**（`crafterPos.relative(facing.getOpposite())`）。**纳管按位置语义**（2026-11-20 按用户反馈放宽）：连接器只要恰在合成器背面就纳管它，与连接器自身 FACING 无关——对着相邻连接器侧边点击放置也算背贴。旧版要求 FACING 与合成器一致，重放时点击面不同就整链 fail-closed 拒绝，反直觉，已废除。FACING 仅作放置提示：放置点若在某合成器背面则优先指向它，否则按点击面反向。侧贴/顶贴（不在任何合成器背面）只作为网络中继，不纳管。
- 背面在朝向轴上，不参与扳手连接组（`shouldConnect` 排除同轴邻居），不破坏现有 `ConnectedInput`。
- 被动网络节点（BE 无应力/无 tick）；被它纳管的合成器由几何背贴关系决定（`ExtremeConnectorBlock.attachedCrafterPos(Level, BlockPos)` 水平四邻扫描）。
- 连接器相邻即组网；CT 判据：连接器↔连接器 或 连接器↔终端（`ExtremeConnectorCTBehaviour`，全向 OMNIDIRECTIONAL）。

## B29 终焉动能合成终端 `extreme_crafting_terminal`

非动能方块，自身不耗应力；右键开 GUI。

### 网络发现、完整单根与网格坐标（`CraftingTerminalNetwork`）

- `findConnectors`：从终端相邻连接器 BFS 扩展（相邻连接器相连）；只读已加载区段，任一待检查邻居未加载即 fail closed；BFS 访问预算 4096。
- `findCrafters`：每个连接器按位置语义纳管所有"背面正好是它"的合成器（水平四邻扫描，连接器→合成器方向 = 合成器朝向），按位置去重；侧贴/顶贴只中继。
- **完整单根**：managed 合成器必须构成一条完整单根链——唯一输出根、无多根、无环、无坐标碰撞，且每个实际入/出邻居都被连接器纳管；缺一台连接器、半条链、断链都返回 `null`，不会拿半条链起工。输出根是唯一没有 target 合成器的节点。
- **每台可 tick**：起工前逐台检查合成器所在区块 `isPositionTicking` 且实体已加载；任一不 tick 就整网拒绝，避免把材料投进不会运行的 BE。
- **81 台上限**：managed 节点硬上限 81（9×9 配方输入上限）；超过直接拒绝，换取有界扫描。
- **品类边界**（2026-11-20 放宽）：B26 炽骨立方合成器可被终端纳管；准入按根品类收窄——炽骨网络仅 Avaritia 前两档 + B31 `blaze_cube_crafting`，终焉网络全白名单 + B31（`supportsAutoCraftFor`）。跨系列混链仍由 `canConnect` 天然拒绝，合法单链必为单一品类。终焉锻造器只要真实链规则允许就可作为同链节点参与。
- `gridCoords`：从唯一输出根沿 target 反向边迭代推算，`coord(c) = coord(target(c)) + offset(c.pointing)`，输出根 `(0,0)`；offset：LEFT→x+1 / RIGHT→x-1 / DOWN→y+1 / UP→y-1。环、未到达节点、坐标碰撞都返回空。
  **注意**：朝北时实测 RIGHT→西、LEFT→东，网格 x 轴相对世界 X 反向。

### 配方列表与准入

- 列表只来自客户端已同步的真实 `RecipeManager`；按支持的数据包配方类型与真实布局重建，数据包重载后（签名变化）自动刷新。
- 客户端列表、SELECT、CRAFT 共用同一准入（`supportedLayout`）：类型受支持、产物非空、布局不超过 9×9、每个非空 `Ingredient` 能枚举候选；避免“界面能点、服务端不认”。
- 精确白名单：`ExtremeKineticCraftingRecipe`、标准 `ShapedTableCraftingRecipe`、`ShapelessTableCraftingRecipe`，以及仅额外覆写返还物的 `NoConsumeCatalystShapedRecipe`；其余不进入列表/起工。
- 明确拒绝三个依赖隐藏 components/contents 的特殊类：`FullMatterClusterRecipe`、`EternalSingularityCraftRecipe`、`InfinityCatalystCraftRecipe`；它们无法从公开 `Ingredient` 稳定推导候选。

### 起工预检（只模拟，不动实物）

1. **单次启动**：一次点击只起一单；网络里已有本单、任一合成器非 IDLE，或目标槽/聚合非空、合成器有待投递暂存时返回 `BUSY`，不排队、不二次抽料。
2. **有序/无序真实布局预检**：有序按图案，允许镜像时普通/镜像都试；无序按近似方阵，在真实网格坐标上选空格。布局必须在真实合成器网格里放得下，不是只看包围盒。
3. **先模拟并核对原料**：逐槽 `extractItem(..., true)` 模拟可抽数量，按物品 + components 分组，用容量匹配（最大流）处理同一材料多格竞争；此阶段不抽任何实物。
4. **仓库取料面**：终端六个相邻面逐一查询，面参数一律用**朝向终端的那一面**（`terminalPos.relative(direction)` 的 `direction.getOpposite()`），避免 sided inventory 从错误面取料；合成器/连接器/终端自身不作为仓库，同一 handler 去重。
5. **虚拟空格**：用所有 managed 合成器坐标建 `GroupedItems` 虚拟网格，空格填 `ItemStack.EMPTY`；再把候选材料填入配方格，用**本单精确 recipeId** 调真实 `matches` 复核最终输入。
6. **不制作实物盖板**：空配方格只存在于虚拟网格，不消耗/安装/移除 `create:crafter_slot_cover`，也不改任何合成器的真实 `covered` 状态。所需格已有手工料或真实盖板时预检失败，绝不自动摘除。
7. **失败零变更**：预检任一失败（不支持、网格不匹配、缺料、目标格占用）都不抽物品、不动手工料/盖板、不弹出现有库存；占用槽按 `BUSY` 拒绝，不进入抽取。

### 提交事务与回滚

- 提交前再次核对整链：root/成员/坐标/IDLE/空格/无真实盖板/速度非零；材料抽取后再核对一次。
- 逐笔抽取，每笔复核原 handler/slot 的物品与 components；全部成功后才调用 `startTerminalCraft` 写入各合成器。
- **提交失败按原来源退回**：逆序退还未完成的本单材料；原槽优先，其次同一 handler 其它槽；handler 只出不进/插入拒绝时，余料先尝试**掉在终端处**。第三方 handler 多返回的余料同样退回/掉落。
- **掉落被拒的存档暂存**：若 `ItemEntity` 正式 `spawn` 返回 `false`，终端写入 `RefundBuffer`、合成器写入 `TerminalPendingDrops`（BE NBT）；每次 `lazyTick` 低频重试，只有 `addFreshEntity` 成功后才移除原副本。暂存非空时终端拒绝新单，单次任务最多 81 个栈，避免无界累积。
- **暂存限制**：暂存依附 BE。终端/合成器方块被拆且其它模组仍拒收时，终端已不存在只记录错误、合成器 BE 消失，不保证继续投递或找回；暂存实体否决/reload 目前是代码审查路径，尚无实测日志明确。
- 写入阶段任一节点失败：回滚已写节点（`revertTerminalCraftStart`）并按上述顺序退回已抽材料；不弹出、不清空原有手工料或盖板。

### 本单任务与运行期

- 起工为整链每个节点写入同一 `jobId`、原 root、本单 `recipeId` 和预期 target；root 另存整链成员表。root 只按本单 `recipeId` 精确合成，失配即取消，绝不回退到其它配方或其它链（**按本单唯一定义出货**）。
- 运行中每 tick 校验 root/成员/预期 target/前置是否同任务；**改箭头**、拆目标、断链或混入手工料都会安全取消本单。取消按持久化成员表只回收同 `jobId` 节点的本单原料，从各节点弹出，不沿动态链误弹无关手工料。
- **动力停转时合理暂停**：运行中速度归零只冻结该节点倒计时并保留任务，恢复动力后继续；起工前速度为零则返回 `NO_POWER`。
- 输出根箭头指向输出容器（如箱子）；无 target 合成器的节点才允许作为 root。

### GUI、菜单与会话

- 菜单三重绑定：`menuId`（容器 id）+ 打开时坐标 + 服务端解析到的同一 BE 实例；网络包 `CraftingTerminalPacket` 逐一校验，超距/拆方块/换 BE/伪造包都静默丢弃。
- **当前会话选择**：选择只写本菜单会话；服务端 SELECT 用真实 `RecipeManager` + `supportedLayout` 校验后写入，并更新 BE 的“最近选择”。**最近选择作为默认值**：下次打开菜单以 BE 记录为初值；另一个玩家在同一终端改选择不会改掉本会话的 CRAFT 目标。
- 面板状态：`STARTED` / `INVALID_RECIPE` / `INVALID_NETWORK` / `BUSY` / `NO_POWER` / `GRID_MISMATCH` / `MISSING_MATERIALS` / `TRANSFER_FAILED`；动力不足显示 `NO_POWER`；网络占用/未完成、目标槽已有物品或聚合非空、合成器有待投递暂存等返回 `BUSY`；提交抽取失败或终端退款暂存未清返回 `TRANSFER_FAILED`。结果走菜单 `ContainerData`，屏内显示。
- **网络红字区分（2026-11-20 诊断改进）**：BE 同步 `connectorCount`（相邻 BFS 连接器数）。`crafterCount==0` 且 `connectorCount==0` → `network.missing`（无连接器网络）；`crafterCount==0` 但 `connectorCount>0` → `network.incomplete`（链不完整：查朝向与箭头 / Chain incomplete: check facing）。起因：用户拆放连接器后 FACING 随点击面改变，旧版背贴判定整链 fail-closed 拒绝，旧文案误报"无连接器网络"。同日进一步把纳管放宽为位置语义（见 B30 节），朝向不再影响纳管；`network.incomplete` 现覆盖"少贴连接器/箭头断链"等剩余 fail-closed 情形。自检含回归：2×2 夹具根连接器故意朝 EAST（模拟侧边点击放置）仍照常纳管起工。复核 `RESULT 107/107 · DONE ALL PASS`（日志 `/tmp/diag-selftest.log`、`/tmp/possem-final.log`）。
- 基础中英支持：GUI 标题、按钮、状态、提示均有 `en_us` / `zh_cn` 键。

`lazyTick` 汇总网络内合成器 `calculateStressApplied()*|getSpeed|`，同步给 GUI 显示；终端自身不耗应力。

## 最短真实手工演示：3×2 `avaritia:crystal_matrix_ingot`

真实 JSON 校对（`libs/Re-Avaritia-neoforge-1.21.1-1.4.1-release.jar` 内 `data/avaritia/recipe/crystal_matrix_ingot.json`）：

- `type=avaritia:shaped_table`，`tier=1`
- `pattern=["xyx","xyx"]`
- `x=avaritia:diamond_lattice`（钻石晶格），`y=minecraft:nether_star`（下界之星）
- 结果 1 个 `avaritia:crystal_matrix_ingot`

因此是 **4 个钻石晶格 + 2 个下界之星**，不是 4 个钻石块；钻石晶格本身按同 jar 的 `diamond_lattice.json`（`avaritia:shaped_table`，tier 1，图案 `x x` / ` y ` / `x x`）由 4 钻石 + 1 下界合金碎片合成（普通工作台配方 `diamond_lattice_normal.json` 则是 8 钻石 + 1 碎片；演示按 tier 1 配方）。

### 摆法

以输出根 R 为 `(0,0,0)`，x 向东、y 向上、z 向南（背面）。先由玩家面朝南、把 R 放在自己前方，得到 `HORIZONTAL_FACING=北`；其余贴邻放置会自动继承朝向；再用扳手点正面把 `POINTING` 调到表中值。6 台终焉动能合成器全部 `HORIZONTAL_FACING=北`，排成同一 z 平面的 3×2 墙：

| 方块 | 相对坐标 | 朝向 | POINTING | 指向 |
| --- | --- | --- | --- | --- |
| R（输出根） | `(0,0,0)` | 北 | DOWN | 下方输出箱 `(0,-1,0)` |
| B1 | `(1,0,0)` | 北 | RIGHT | R |
| B2 | `(2,0,0)` | 北 | RIGHT | B1 |
| T0 | `(0,1,0)` | 北 | DOWN | R |
| T1 | `(1,1,0)` | 北 | DOWN | B1 |
| T2 | `(2,1,0)` | 北 | DOWN | B2 |

- R 是唯一输出根（没有 target 合成器），网格坐标 `(0,0)`；其余为 B1 `(-1,0)`、B2 `(-2,0)`、T0 `(0,1)`、T1 `(-1,1)`、T2 `(-2,1)`，正好 3×2。网格 x 轴与物理 X 反向，但 `xyx/xyx` 左右对称，普通/镜像摆放都可。
- 输出箱放在 R 正下方 `(0,-1,0)`，R 的箭头向下指向它。
- 6 台合成器背面（南侧 `z=1`）各贴一个连接器：对着合成器南面放置，连接器 FACING 自动朝北；6 个连接器相邻成网。终端放在 R 连接器正后方 `(0,0,2)`，与任一连接器相邻即可。
- 输入箱放在终端旁边，例如 `(1,0,2)`；终端用箱子朝向自己的那一面取料。箱内放 4 个钻石晶格 + 2 个下界之星。
- 动力用**小齿轮**：齿轮轴向与合成器一致（南北轴），创造马达轴端顶住小齿轮，相邻合成器共享啮合；不要贴合成器正面直接取力。让 6 台都转、GUI 显示应力足够后再起工。
- 右键终端，选 `avaritia:crystal_matrix_ingot`，点“自动合成”。成功后输出箱得到 1 个水晶矩阵锭，输入箱恰好少 4 个钻石晶格和 2 个下界之星；不会产生实物盖板。运行中改箭头/断链会取消并弹出本单原料，动力停转会暂停。

## 2026-11-20 扩展：形状过滤 / 书签红石 / 创造板条箱 / 无线漏斗决策

### 按网络数量与摆放过滤配方列表

- BE 同步 `gridCells`（x,y,covered 三元组）与 `networkBlaze`；`TerminalCraftPlanner.fitsShape(cells, recipe)` 只按数量/摆放/盖板判断放不放得下（有序复用 `findPlacement` 锚点枚举+镜像开关，无序按未覆盖格计数），不做材料匹配。
- 客户端列表、SELECT、CRAFT 共用 `ExtremeCraftingTerminalMenu.supportsLayoutFor(recipe, registries, terminal)`：基础白名单 + 品类收窄 + 形状过滤；0 台网络不展示任何配方。网络形状/品类变化（`networkSignatureOf`）与数据包重载同样触发列表重建。
- 起工侧 `tryStartCraft` 仍走完整 plan（含材料），形状不符返回 `GRID_MISMATCH`。

### 书签钉住 + 红石自动合成

- GUI「钉住/取消」按钮（`KIND_PIN=2`，服务端按当前网络准入校验后写 BE `pinnedRecipeId`，持久化+同步）；钉住配方作为打开菜单的默认选择（`getDefaultRecipeId`，块 openMenu 与菜单构造同口径）。
- 红石：`tick()` 检测 `hasNeighborSignal` 上升沿立即 `tryStartCraft(pinned)`（短脉冲不丢）；`lazyTick` 持续供电期间低频重试（BUSY 跳过、空闲即起工）→ 流水线连续生产。失败分支全部在副作用前返回，沿用原契约。

### 创造板条箱免材料兼容

- 相邻创造板条箱**未设过滤**时视为无限供料：`match()` 为每个需求补合成 `OfferSource(null,-1)`（真实仓库来源排在前面优先），`extractOne` 对 null handler 按模板供 1、不抽实物，`refundAll` 跳过合成来源。已设过滤的创造板条箱本就经 `BottomlessItemHandler` 标准 IItemHandler 语义走真实仓库扫描，无需特殊处理。
- 语义=免材料，不是免配方：产物仍由所选配方定义。

### B32 无线物品漏斗兼容（锚点模型；2026-11-20 实施并按用户纠正改型）

- **终端自身不持有频率、无频率 UI**。在终端六邻面放无线物品漏斗作"频道锚点"（用漏斗自己的配置 GUI 绑频即可），终端读锚点的 `WirelessKey`（频率+所有者+可见性）。
- `TerminalCraftPlanner.addWirelessFunnelSources`：邻面锚点 → `WirelessNetwork.peers(level, anchor.getKey(), anchor)` 取同频道设备 → 其中 `EXTRACTING` 模式漏斗的货源容器（背后优先、开口侧容错，与漏斗 `facingInventory` 同语义）作为远程仓库；锚点自身若也是抽取端，其货源一并纳入。距离口径 `WirelessService.withinRange(terminal, funnel, WirelessConfig.itemFunnelRange())`（默认 64 格）；已加载检查+排除任务机器+身份去重。
- 隐私由频道键天然保证：`peers`/`canPairWith` 只返回同频率+同可见性+同所有者的设备（私有不能连公用），他人私有频道表现为普通 `MISSING_MATERIALS`，不泄露频道存在。
