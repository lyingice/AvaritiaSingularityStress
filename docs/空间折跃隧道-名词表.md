# B15 空间折跃隧道 · 标准名词表

> **用途**：描述改进方向时直接引用这里的术语。你写术语，我落到代码，避免"输入端/方向/频道"这类多义词来回猜。
> **依据**：`WarpTunnelBlock.java` / `WarpTunnelBlockEntity.java` / `WarpTunnelItem.java` 的当前实现（2026-11-04）。
> **警告**：`docs/空间折跃隧道-设计稿.md` 里的「频率配对 / 入口端 / 出口端 / SelectionMode」**已被实现取代**，那份文档是旧版，不要再用那些词描述。

---

## 0. 先纠正三个最容易被误用的词

| 你可能说 | 现状 | 应该说 |
| --- | --- | --- |
| 输入端 / 出口端 / 入口端 | **角色概念已不存在**。任何一台隧道都可以既是来源又是终点，取决于它的哪个面被绑 | **出向面**（往外送的面）/ **终点面**（接收的面） |
| 频道 / 频率 | **B15 不实现 `IFrequencyBindable`**，频率卡对它没有作用 | **绑定** |
| 方向 / 出口方向 | 出口不是"选一个方向"，而是"绑到哪台机器的哪个面" | **终点面** |

## 1. 空间与面

| 术语 | 代码符号 | 定义 |
| --- | --- | --- |
| **隧道方块** | `WarpTunnelBlock` | 挂在水平传送带上的设备，继承 Create 黄铜隧道 |
| **绑定面** | `Direction`（`NORTH/EAST/SOUTH/WEST`） | 隧道四个侧面之一；上下两面不参与（`bindableFace`，`WarpTunnelBlock.java:307`） |
| **带子面** | `beltSides` | 这一面外侧有传送带进出（由 `SHAPE` + `HORIZONTAL_AXIS` 推出），是"能不能绑"的前置条件 |
| **视窗** | `SHAPE`（`CLOSED` / `WINDOW`） | 隧道的"窗口"外观，**潜行 + 扳手**切换 |
| **红石停机** | `POWERED` | 通电后整机停止投递，队头不动（`WarpTunnelBlockEntity.java:240-243`） |

## 2. 链路与配对（核心）

| 术语 | 代码符号 | 定义 |
| --- | --- | --- |
| **定向链路** | `Link(BlockPos pos, Direction face, boolean incoming)` | 一个面上的"通往哪里"记录。`pos`=对端隧道，`face`=对端那个面 |
| **出向链路** | `incoming == false` | 物品会从本面流向对端。**只有出向链路的机器才会送东西** |
| **反向指针** | `incoming == true` | 对端那侧的记账，只用来防止物品弹回、解绑时能对称清除 |
| **绑定** | `bind(a, faceA, b, faceB)` | 一次性建立 **A.faceA → B.faceB** 的单向链路（A 记出向、B 记反向指针） |
| **解绑** | `unbind(face)` | 清掉本面链路，并对端那一面一起清（`WarpTunnelBlockEntity.java:199-209`） |
| **待绑定** | `Pending(pos, face, gameTime)` | 扳手点下第一面后，等第二面的中间状态；**600 tick（30 秒）不点第二面自动过期** |
| **单向** | — | 一次绑定只允许一个方向。要双向 = **再绑一次反向** |

> 一句话：**链接是"面 → 面"的，而且是单向的；没有"入口机器 / 出口机器"这种机器级角色。**

### 2.1 三条实机修正（2026-11-04，别再改回去）

| 修正 | 之前的行为 | 现在 | 证据 |
| --- | --- | --- | --- |
| **绑定不要求那一面有带子** | `hasBeltOn(face)` 为 false 就把扳手交还去切视窗，既不记 Pending 也不绑定 | 只要求是四个侧面之一 | 日志 `outgoing=[NONE]`，玩家点朝对端的面绑不上 |
| **判定扫所有出向面** | 只查「入口面的对面」（`outFace`）那一条链路 | 先查入口对面，再按 北→东→南→西 扫其余出向面 | 日志 `from=north out=south` 而链路在 `north` |
| **选路优先「入口面」** | `processHead` 只按 FACES 固定顺序，多出口必然串线 | 队列记录入口面；选路顺序 = **入口面 → 入口对面 → FACES 顺位** | 日志 `from=west out=east links=[north,west]` 却走了 `north`；修正后 `SEND face=west` / `face=north` 各走各的 |

道理：**绑定面只是逻辑出口，真正投放发生在对端那一面**（`releaseAt(peer, link.face())`），所以本机那一面有没有带子、是不是物品流出的方向，都不该成为绑定前置条件。

**绑定语义定稿**：把链路绑在某一面 = "从这一面进来的物品送往对端"。所以入口面是首选依据，入口对面（带子自然穿过的方向）是次选，其余面只在两者都没链路时顺位补。

## 3. 数据流（从带子到终点）

| 术语 | 代码符号 | 定义 |
| --- | --- | --- |
| **吸收** | `absorbIncoming()` | 把带子交来的整堆塞进本机队列；塞不下的**留在原处**（背压） |
| **队列** | `queue` | 本地缓冲，**4 堆**（`MAX_QUEUED_STACKS`） |
| **队头** | `queue.get(0)` | 当前要送出的那一堆 |
| **批发** | `BATCH = 16` | 单次最多投递的个数 |
| **节流** | `TRANSFER_INTERVAL = 5` | 每 5 tick 处理一次队头 |
| **分流扫描** | `processHead()` | 按 **北 → 东 → 南 → 西** 的固定顺序，找**第一个**「出向链路 且 过滤命中 且 投递成功」的面 |
| **固定优先级** | `FACES` 顺序 | **不是轮询**。同一种物品永远走同一个面，除非那面失败才顺位下一个 |
| **投递** | `trySend()` | 依次检查：对端是否加载 → 是不是隧道 → 是否超距 → 交给 `releaseAt` |
| **投放点** | `releaseAt()` | 四级：①终点面外侧带子的输入口 ②该面容器 ③带子前进方向无阻挡则带尾抛出 ④兜底到对端下方带子 |
| **背压** | — | 队列满 → 不再吸收 → 带子被堵住（不是丢物品） |
| **停滞** | — | 物品停在带子上不进机器 |

## 4. 面级过滤

| 术语 | 代码符号 | 定义 |
| --- | --- | --- |
| **面级过滤** | `sidedFilter`（Create `SidedFilteringBehaviour`） | 每个出向面一个独立过滤槽 |
| **白点** | `BrassTunnelFilterSlot` | 世界里的四个小白点；点击放/清过滤物品，由 Create 的 ValueBox 客户端拦截 |
| **全收** | 过滤槽为空 | 该面不挑物品 |
| **只收** | 过滤槽有物品 | 只送与过滤槽**同类同组件**的物品 |

> 注意：过滤器只在**分流时筛选**，不改变投放点，也不影响吸收。

## 5. 状态与诊断

`status` 字符串（`WarpTunnelBlockEntity.getStatus()` → Jade / 粒子 / 调试）：

| 值 | 含义 |
| --- | --- |
| `idle` | 队列空，没事做 |
| `warping` | 正在投递 |
| `unbound` | 一个出向链路都没有 |
| `powered` | 红石停机 |
| `peer_unloaded` | 对端所在区块未加载 |
| `bad_peer` | 对端方块不是空间折跃隧道 |
| `out_of_range` | 超出配对距离（`WirelessConfig.warpTunnelRange()`，默认 128 格） |
| `exit_blocked` | 终点面的投放点全堵 |

## 6. 交互入口（六个，互斥）

| 操作 | 行为 |
| --- | --- |
| **空手右键**（不潜行） | 让位——四个白点由 Create 的 ValueBox 处理，不抢 |
| **潜行 + 空手右键** | 查看该面状态：绑定目标坐标 + 过滤物品 |
| **扳手右键** | 该面已绑定 → **解绑**；未绑定且有上一个面 → **建立绑定** |
| **潜行 + 扳手右键** | 切换视窗 `CLOSED ⇄ WINDOW`（交还父类） |
| **频率卡右键** | 无作用（B15 不实现频率绑定） |
| **点白点** | 放/清该面的过滤物品 |

## 7. 本版明确不做（描述时别提出这些为前提）

- ❌ **跨维度**（频道/配对表按维度分区）
- ❌ **机器级角色**（入口/出口端切换）
- ❌ **频率配对**（已废弃）
- ❌ **轮询分流**（现在是固定优先级）
- ❌ **一对多广播**（一个面只存一个 `Link`）
- ❌ **双向同时传**（要双向得绑两次）

## 8. 描述模板（照这个填，我就能直接开工）

```text
【改进编号】B15-补丁N（或新编号 B2x）
【影响层】空间/链路/数据流/过滤/状态/交互（选一个或几个）
【现状】现在 <某个术语> 的行为是 <可观察现象>
【期望】把 <某术语> 改成 <新行为>
【触发条件】当 <玩家做什么 / 什么时候>
【边界】哪些情况**不**改变（例：不影响吸收、不影响背压）
【验收】1) … 2) … 3) …
```

**示例（合格）**：

> 【影响层】数据流
> 【现状】`processHead` 按北→东→南→西固定顺序找**第一个**可用面，同种物品永远只走一面。
> 【期望】支持**轮询**：同一物品在多个可用出向面之间轮流投递。
> 【触发条件】队头物品存在 ≥2 个「过滤命中且投递成功」的面时。
> 【边界】只有一个可用面时行为不变；不过滤物品的分配顺序；不影响队列容量。
> 【验收】1) 放两面各一个空箱，连续投 10 组，两组箱子的数量差 ≤1；2) 拆掉一面后全部走剩下那面。
