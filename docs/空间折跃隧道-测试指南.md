# 空间折跃隧道（B15）· 实现说明与测试指南

> 本轮按你新给的设计重写了实现：**单端口 · 一面两槽 · 频道配对 · 缓冲队列**。
> 上一版设计稿（§4 入口端/出口端双角色 + OUTPUT 选面）已被本实现取代，保留它只为记录推导过程。
> 编译与数据生成均已通过（记录见文末）。

---

## 1. 它是什么

放在**水平传送带**上的一台隧道：

- 带上来的物品进隧道后**不再继续沿带子走**，而是按两个过滤槽的判定决定去向；
- 命中**折跃槽** → 跨空间投到同频道的对端端口，落在对端**下方那条传送带**上；
- 命中**物流槽** → 按黄铜隧道的方式本地输出（侧向传送带 / 从带子尽头抛出）；
- 两个槽都靠**白名单 / 黑名单**判定；优先顺序可用扳手切换；
- 投不出去时物品**留在缓冲队列里**，队列满 → 带子停在隧道前（Create 原生停滞）。

## 2. 方块状态与数据

| 项 | 类型 | 说明 |
| --- | --- | --- |
| `shape` | 继承自 Create | STRAIGHT / WINDOW / CLOSED / T_LEFT / T_RIGHT / CROSS（几何与原版一致） |
| `horizontal_axis` | 继承 | 底下带子的水平轴 |
| `powered` | 新增 | 红石通电 → 整机停机（不接货、不投递） |
| 频道 | NBT `Frequency` | 0–9999，-1 = 未设置；复用无线模块的频道机制 |
| 可见性 / owner | NBT | 私有（同 owner 才能配对）/ 公用 |
| 双槽 | NBT `WarpFilter` / `LogisticsFilter` | 各存 1 个物品作为过滤样本 |
| 黑白名单 | NBT `WarpWhitelist` / `LogisticsWhitelist` | true = 白名单 |
| 优先级 | NBT `WarpFirst` | true = 折跃优先（默认） |
| 回退 | NBT `FallbackToLogistics` | true = 折跃堵塞时允许走物流（默认开） |
| 缓冲队列 | NBT `Queue` | FIFO，最多 **4 堆** |
| 状态 | NBT `WarpStatus` | 供渲染/调试用 |

## 3. 操作表（这是进游戏最需要的）

| 操作 | 效果 |
| --- | --- |
| **空手右键**（点在方块上任意位置） | 打开频道界面（设频道号 / 私有公用） |
| **手持物品右键** | 把手上物品设为过滤样本：点在**左半** → 折跃槽；点在**右半** → 物流槽（左/右按带子轴向判定，不会消耗物品） |
| **空手潜行右键** | 切换该半边槽的**白名单 ⇄ 黑名单** |
| **扳手右键** | 切换**优先级**：折跃优先 ⇄ 物流优先 |
| **扳手潜行右键** | 切换**折跃堵塞时是否退回物流** |
| **手持频率卡右键** | 写入频道号（沿用 I3 频率卡逻辑） |
| 红石信号 | 通电停机 |

> 左右半的判定：沿带子轴向，坐标 < 0.5 的一侧是**折跃槽**，另一侧是**物流槽**。
> 渲染上两个槽的位置就是这两个半边的顶面（见第 5 节）。

## 4. 行为判定顺序（代码里的真实逻辑）

```text
带上的物品进入隧道
  → 入队（FIFO，最多 4 堆；满则拒收，带子停在隧道前）
  → 每 5 tick 处理队头：
      warpHit = 折跃槽命中(物品)
      logiHit = 物流槽命中(物品)
      两槽都不命中                → 堵塞（红色粒子 + "no filter match"）
      warpHit 且 折跃成功          → 出队
      warpHit 且 折跃失败：
          允许回退 且 logiHit     → 尝试物流
          否则                    → 堵塞（红色粒子 + 具体原因）
      折跃优先时物流只在"折跃失败/不命中"后发生；物流优先时顺序反过来
```

**折跃成功的条件**（缺一不可）：

1. 频道号已设置；
2. 同频道、**同维度**、处于 `warpTunnelRange`（默认 128 格）内的对端**唯一**（0 台或 ≥2 台都算失败）；
3. 对端是空间折跃隧道（不是同频的漏斗/应力桥）；
4. 对端区块已加载；
5. **对端下方必须是一条传送带**（这是你要求的新规则）；
6. 那条传送带还能塞得下物品。

## 6. 与上一版设计的差异（免得你按旧文档测）

| 项 | 旧设计（已废） | 现实现 |
| --- | --- | --- |
| 角色 | 入口端 / 出口端（EXPORTING 方块状态） | **不再分角色**：每个端口都能收发 |
| 出口方向 | `OUTPUT` 方块状态（4 向） | 折跃 = 落到对端下方带子；物流 = 黄铜隧道式自动找侧向出口 |

| 缓冲 | 1 堆 | **FIFO 队列，4 堆** |
| 频道 | 频率 | 频率（频道号），保留私有/公用与 owner 规则 |

## 7. 进游戏测试清单（照着点一遍就能判断要不要改）

前置：本体 + Create 已加载。

1. **能放下**：拿「空间折跃隧道」放在一条水平传送带上（正对带子顶面）。放不下说明下方不是水平带子。
2. **看得见槽**：空手准星对准隧道，看顶面是否出现 `CH --` 与左右两个 `-`。
3. **设频道**：空手右键 → 界面里把频道设为 1234 → 关掉 → 顶部应变成 `CH 1234`。
4. **两台配对**：另起一条带子，放第二个隧道，也设频道 1234（同一玩家默认私有频道，能配对）。
   → 两个方块上方都不应出现 `no peer`（配对成功后状态会变成空或 `idle`）。
5. **设折跃槽**：手持铁锭，点方块**左半** → 左槽出现铁锭图标并提示"折跃槽设为 铁锭"。
6. **送料**：第一条带子放物品（漏斗/手动丢）→ 物品进隧道后应在**第二条带子上**出现。
   观察：紫粒子、两端各一声传送音效、状态短暂显示 `warp`。
7. **黑名单**：空手潜行右键左半 → 字母 W 变 B → 此时铁锭**不应**被折跃。
8. **物流槽**：在第一条带子侧面接一段横向传送带/箱子，手持物品点**右半**设物流槽 → 物品应从侧面出来。
9. **两槽都不匹配**：设折跃槽为铁锭、物流槽为金锭，送**沙子** → 应堵塞：红粒子 + `no filter match`，沙子留在隧道里，带子被堵。
10. **队列**：堵塞状态继续送料 → 最多吃进 4 堆，第 5 堆开始带子停在隧道前（Create 原生停滞）。
11. **对端无带子**：拆掉第二条带子 → 应显示 `exit: no belt` 并堵塞（不会凭空丢物品）。
12. **红石**：给隧道通电 → 立即停机（`redstone locked`），断电恢复。
13. **拆方块**：破坏带队列的隧道 → 队列里的物品应以掉落物形式返还。
14. **重进世界**：频道、双槽、队列内容都应保留。

如果 4/6 不成立，先看顶部状态文字，它会直接告诉你卡在哪一步（无对端 / 频道冲突 / 对端无带子 / 带子满 / 两槽不匹配）。

## 9. 已知限制 / 待你反馈的点

1. **跨维度未实现**：频道表按维度分区（`WirelessNetwork` 用 `IdentityHashMap<LevelAccessor,…>`）。配置项 `warpTunnelCrossDimension` 已留但默认 false 且**开启也没效果**（代码注释里写明了），要真跨维度得先加全局索引表。
2. **双槽图标位置**是我按"沿带轴左右各 0.22 格"估的，可能与你想要的"左右双槽"观感有偏差；字号/高度都在 `WarpTunnelRenderer` 里，一处常量就能调。
3. **没有 Jade/护目镜信息行**：目前只有世界内文字与动作条提示。要的话我下一轮补（本模组已有 Jade 插件与护目镜范式可照抄）。
4. **物流槽的白/黑名单**同样生效，但物流路径本身仍沿用黄铜隧道"自动找侧向出口"的规则，没有"指定面"。
5. **频率卡写入**沿用 I3 卡片逻辑（私有频道要求卡片 owner 一致）。

| 潜行 + 扳手右键 | 切换优先级：折跃优先 ⇄ 物流优先 |

全部失败 → 堵塞（物品留在 4 堆队列里，带子停在隧道前）。

**已删除**：频道 GUI（`WarpTunnelConfigMenu/Screen/Packet`）、频道号 NBT、无线频道登记（`WirelessDevice`）。
方块实体上方现在显示 `LINKS n`（已绑定面数量）+ 运行状态文字。
### 11.1 v3.1 修正：绑定改为单向

- 扳手绑定只让 **A 面 → B 面** 单向投递；B 那一面只记一条 `incoming` 反向指针（用于解绑/提示），**不参与出口选择**。
  原因：双向都把对方当出口时，物品会在两台隧道之间来回弹（表现为"多弹出一个物品"）。
- 同时修了落点插入的计数 bug（原来把"剩余"当"搬运量"，会多扣或少扣队列里的物品）。

## 12. v4：单槽 + 按面过滤分流（当前实现）

### 12.1 规则

1. **绑定**（扳手）：点 A 的某个面 → 点 B 的某个面 = A 的这个面把物品送到 B 的那个面（单向）。
   B 的那一面只留一条反向指针（用于解绑/提示），不会反过来再发一次 —— 这是之前"多弹一个物品"的根因。
2. **过滤**（每个面一个槽）：手持物品右键某个已绑定的面 = 把该物品设成这一面的过滤；
   潜行 + 扳手右键 = 清空该面过滤；空手右键 = 查看该面绑定目标与过滤内容。
3. **分流**：物品进入隧道后，按 **北 → 东 → 南 → 西** 顺序找第一个「已绑定 + 过滤命中（空槽=收所有）+ 对端可用」的面，送过去。
4. **堵塞**：没有面能收（全不匹配 / 对端未加载 / 出口堵）时物品留在队列（4 堆）里，队满则拒收，传送带停在隧道前。

### 12.2 落点优先级

该面外侧传送带输入口 → 该面对应容器 → 该面是带子前进方向时从带尾抛出 → 兜底对端下方那条传送带。

### 12.3 现状

- 已删除：双槽（折跃/物流）、黑白名单、优先级、回退开关、频道 GUI、无线频道登记。
- 渲染：每个绑定面显示它的过滤物品；空槽显示"任何物品"字样；方块上方显示 `LINKS n` 与运行状态。
