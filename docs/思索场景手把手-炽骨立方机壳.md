# 手把手：给「炽骨立方机壳」自己写一个思索场景

> 这份文档写给**第一次碰 Ponder** 的你。目标：三天后你不看我，也能自己加一幕、挪一个方块、改一句台词。
> 当前代码状态：**编译通过**，`.nbt` 已是最新布局。剩下"进游戏看效果"那一步由你自己截图给我。

---

## 0. 先记住这一件事

Ponder 场景 = **一份 3D 结构（.nbt）** + **一段播放脚本（Java）** + **一份文案（lang）**。

三者靠**一串名字**绑在一起。名字错一个，界面上就是空白或者一串 `ponder.xxx.header`。

```
组件 id（物品）─┐
                ├─→ 剧本 id "blaze_cube_casing" ─┬─→ 找结构文件 ponder/blaze_cube_casing.nbt
                │                                └─→ 拼文案键  <modid>.ponder.blaze_cube_casing.text_1
                └─→ 弹窗标题
```

---

## 1. 你现在有哪几个文件

| 文件 | 作用 | 你平时会改它吗 |
| --- | --- | --- |
| `src/main/java/.../ponder/BlazeCubePonderScenes.java` | **剧本 + 注册**（主要战场） | 天天改 |
| `src/main/java/.../ponder/ASPonderPlugin.java` | 插件入口，告诉 Ponder "我是谁" | 加新场景时改 |
| `src/main/java/.../ponder/ASPonderClientSetup.java` | 客户端挂载，把插件塞进 Ponder | 基本不动 |
| `src/main/resources/assets/avaritia_singularity_stress/ponder/blaze_cube_casing.nbt` | 结构文件（**不要手改**） | 由脚本生成 |
| `tools/gen_ponder_schematic.py` | 生成上面那个 .nbt 的脚本 | 改布局时改 |
| `src/main/java/.../init/provider/ModLanguageProviderZhCn.java` | 中文文案 | 改台词时改 |
| `src/main/java/.../init/provider/ModLanguageProvider.java` | 英文文案 | 改台词时改 |

**为什么结构文件要用脚本生成？**
因为 Ponder 读的 `.nbt` 是原版 `StructureTemplate`（GZIP + NBT），正规做法是进游戏用结构方块 SAVE 再拷出来。那样每次挪一个方块都要重进游戏，没法版本管理。脚本直接写出同格式，改坐标就是改 Python 里一行。

## 2. 剧本文件逐段拆解（`BlazeCubePonderScenes.java`）

打开文件，对照行号看。下面每一段我都标了"这行在干嘛 / 删了会怎样"。

### 2.1 骨架（第 78–89 行）

```java
CreateSceneBuilder scene = new CreateSceneBuilder(builder);   // 包一层，才能用转速/旋转指示这些 Create 专属工具
scene.title(SCENE_CASING, "Blaze Cube Casing");              // ① 剧本 id  ② 编辑模式下的默认标题
scene.configureBasePlate(0, 0, BASE_SIZE);                   // 底板起点 + 尺寸（5 = 5x5）
scene.idle(5);                                               // 空转 5 tick
```

- `title()` 第一个参数**不是**给人看的文字，它是**钥匙**：结构文件和文案键都拿它拼。
- `idle(n)` 的单位是 **tick**，20 tick = 1 秒。**每个动作后面必须给 idle**，否则画面一步跳到下一步，看着像卡死。

### 2.2 选位置（第 91–96 行）

```java
Selection powerLine = util.select().fromTo(0, MACHINE_Y, LANE_Z, 5, MACHINE_Y, LANE_Z); // 一整条线
Selection shaftSpot = util.select().position(1, MACHINE_Y, LANE_Z);                     // 单格
BlockPos   shaftPos = util.grid().at(1, MACHINE_Y, LANE_Z);                             // 单格的坐标
```

两种对象别混：

| 类型 | 从哪来 | 给谁用 |
| --- | --- | --- |
| `Selection`（一片方块） | `util.select()...` | `showSection` / `setBlocks` / `setKineticSpeed` |
| `BlockPos`（一个点） | `util.grid().at(x,y,z)` | `showControls` 的落点、`effects()` 的指示器 |

`MACHINE_Y = 1`、`LANE_Z = 2` 是常量（第 71–73 行）。改这两个数 = 整条线整体升降/前后挪。

### 2.3 让结构出现（第 101–109 行）

```java
scene.world().showSection(util.select().layer(0), Direction.UP);  // 地面从下往上冒出来
scene.idle(10);
scene.world().showSection(powerLine, Direction.DOWN);             // 机器从上往下掉下来
scene.idle(20);
scene.world().setKineticSpeed(powerLine, 32);                      // 给转速 32 RPM
scene.effects().rotationDirectionIndicator(shaftPos);             // 画个转向箭头
```

`Direction.UP/DOWN/EAST...` 是"方块从哪个方向进场"，**不是**机器的朝向。

### 2.4 台词（第 112–117 行）

```java
scene.overlay().showText(70)          // 显示 70 tick（3.5 秒）
        .text("Blaze Cube Casings can wrap kinetic blocks in a blaze-forged shell")  // 默认英文
        .attachKeyFrame()             // 打一个关键帧：玩家能把进度条拖到这一句
        .placeNearTarget()            // 文字贴着目标放
        .pointAt(util.vector().topOf(shaftPos));   // 从文字拉一根线指向这里
```

**这段英文玩家看不到。** 玩家看到的是 lang 文件里 `text_1` 的内容。英文只是编辑模式下的占位。

编号规则：**按 `.text()` 调用顺序从 1 开始**。你在中间插一句，后面全部顺移——所以改完一定要回头核对 lang。

### 2.5 演"右键包壳"（第 120–128 行）

```java
scene.overlay().showControls(util.vector().topOf(shaftPos), Pointing.DOWN, 60)  // 60 tick 内画一个手势气泡
        .rightClick()                                                          // 右键图标
        .withItem(casingStack);                                                // 手上拿着机壳
scene.idle(7);                                                                 // 让手势先"落下"
scene.world().setBlocks(shaftSpot, encasedShaft(), true);                      // 真的把方块换掉（true = 出粒子）
scene.world().setKineticSpeed(powerLine, 32);                                  // ★ 必须重给转速
scene.effects().indicateSuccess(shaftPos);                                     // 打绿勾
```

**`★` 那行是这次最关键的发现**：`setBlocks` 换掉方块后，新的方块实体是"没有速度"的，不补这一句，被包住的那一格当场停转。

### 2.6 收尾（第 158 行）

```java
scene.markAsFinished();   // 不写这句，场景会停在最后一帧不结束
```

## 3. 五个改动配方（照着抄就行）

### 配方 A：改一句台词

要改第 1 句（"能把传动部件包起来"）。

1. 改默认英文：`BlazeCubePonderScenes.java:113` 的 `.text("...")`
2. 改中文：`ModLanguageProviderZhCn.java` 搜 `blaze_cube_casing.text_1`，改后面那个字符串
3. 改英文：`ModLanguageProvider.java` 同一个键
4. 跑一次 datagen（下面第 4 节）

> 只改代码不改 lang = 玩家看到的还是旧文案。

### 配方 B：把整条机器往后挪一格

1. `BlazeCubePonderScenes.java:73` 把 `LANE_Z` 从 `2` 改成 `3`
2. `tools/gen_ponder_schematic.py` 里 `LANE_Z = 2` 也改成 `3`
3. 重新生成 `.nbt` + 编译（第 4 节）

**两边必须一起改**。只改一边，方块会出现在别的地方，或者干脆不出现。

### 配方 C：加第 4 幕（比如"包壳后用手拧扳手能拆开"）

在 `markAsFinished()` 之前插一段：

```java
    // ---------------- 台词 4：拆掉外壳 ----------------
    scene.overlay().showControls(util.vector().topOf(shaftPos), Pointing.DOWN, 60)
            .rightClick()
            .withItem(new ItemStack(AllItems.WRENCH.get()));
    scene.idle(7);
    scene.world().setBlocks(shaftSpot, AllBlocks.SHAFT.getDefaultState()
            .setValue(RotatedPillarKineticBlock.AXIS, Direction.Axis.X), true);
    scene.world().setKineticSpeed(powerLine, 32);
    scene.idle(20);

    scene.overlay().showText(70)
            .text("A wrench pops the casing back off")
            .attachKeyFrame()
            .placeNearTarget()
            .pointAt(util.vector().topOf(shaftPos));
    scene.idle(80);
```

然后**必须**去 `ModLanguageProviderZhCn.java` 补一条 `text_4`（因为这句是第 4 个 `.text()`）。

### 配方 D：换一台机器来演

把 `encasedShaft()`（第 163 行）里换掉方块：

```java
return ModBlocks.别的包壳方块.get().defaultBlockState()
        .setValue(RotatedPillarKineticBlock.AXIS, Direction.Axis.X);
```

`AXIS` 是所有轴/齿轮族共用的属性（来自 `RotatedPillarKineticBlock`），别自己猜属性名。

### 配方 E：再加一个完全新的场景

1. 在 `BlazeCubePonderScenes` 里写一个新方法，签名必须是 `(SceneBuilder, SceneBuildingUtil)`；
2. 在 `registerScenes()`（第 60 行附近）加一行：
   ```java
   helper.addStoryBoard(另一个组件id, "我的新场景id", BlazeCubePonderScenes::我的方法, TAG_BLAZE_CUBE);
   ```
3. 用脚本生成 `我的新场景id.nbt`；
4. 补 `<modid>.ponder.我的新场景id.header` / `.text_1`…

## 5. 我这次踩到的坑（你直接跳过）

| 症状 | 真实原因 | 怎么修 |
| --- | --- | --- |
| 场景里机器是"死方块"，不转 | 方块**孤立**，没连成动力线 | 至少 3 格连起来，像这次的轴-轴-轴-齿轮-轴-轴 |
| 包壳的那一格当场停转 | `setBlocks` 后新方块实体没有速度 | 紧跟一句 `setKineticSpeed(整条线, 32)` |
| 包壳后的方块**看不出是轴/齿轮** | 包壳方块的模型只有外壳，转动部分由 Flywheel 的 visual 画；世界里正常，Ponder 里可能不画 | 待确认（见下） |
| 两个包壳块并排糊成一块 | 包壳点相邻 | 隔开一格（这次是 x=1 和 x=3） |
| 界面显示 `ponder.blaze_cube_casing.header` | lang 键错了或者 datagen 没跑 | 核对键名 + `./gradlew runData` |
| 改了 .nbt 游戏里没变化 | 读的是 `build/resources/main` | 跑 `./gradlew processResources`，再 F3+T 或重启 |

### 还没解决的一件事（需要你的截图来判断）

我在**游戏世界里**看到你摆的炽骨立方齿轮箱——**齿轮齿盘是能看见的**。
但在 **Ponder 场景里**，包壳后的方块只剩机壳外壳，齿轮/轴心看不见。

这说明不是方块本身坏了，而是 **Ponder 的渲染环境不画 Flywheel visual**。

要确认它是不是 Create 也这样，最直接的办法：在游戏里放一下原版那一幕

```
/ponder create:cogwheel_casing
```

然后看它的包壳齿轮箱**有没有齿轮齿盘**，截图给我：

- 如果原版也看不见 → 这是 Ponder 的普遍限制，咱的场景只能接受，或者改用"不包壳、只展示机壳方块"的讲法
- 如果原版看得见 → 是咱的 `ModVisualizers` 注册在 Ponder 下没生效，得单独修
