# B27 终焉钻头 / B28 终焉水车

## B27 终焉钻头 `extreme_drill`

沿用 Create 机械钻头（`DrillBlock`/`DrillBlockEntity`）的朝向、形状、水logged、实体伤害与挖掘状态机，仅覆写两处：

- **耗能 256 SU/RPM**：`ModStress` 注册 `IMPACTS=256`（1RPM 基准）。总耗能 = 256 × 转速；256RPM 时 65536 SU。
- **几乎立即挖掘**：覆写 `getBreakSpeed()` 为 `|speed| × 100`（原版为 `|speed|/100`，见 `BlockBreakingKineticBlockEntity.java:157-159`）。破坏进度单 tick 直达 10，任意可破坏方块近乎瞬破。
- **时运随转速线性增长 + 可配置额外乘区**：基础等级 `getBaseFortuneLevel() = clamp(floor(|speed|/16), 0, 16)`，即 16RPM→1 级、32→2、…、256→16，每 16RPM 一级，低于 16 无时运，高于 256 截断 16；有效等级 `getFortuneLevel() = 基础 × fortuneMultiplier`（SERVER 配置 `ExtremeDrillConfig`，**默认 5**，范围 1~256，即 256RPM 默认时运 80）。配置文件 `avaritia_singularity_stress-drill-server.toml`（同 modid 第二个 SERVER config 必须独立文件名，否则 ConfigTracker 冲突）。
  掉落覆写 `onBlockBroken`，用带时运附魔的钻石镐工具调用 Create `BlockHelper.destroyBlockAs`（`BlockHelper.java:213-264`），它把工具传给 `Block.getDrops`，时运按真实等级生效（可超过原版上限 3）。`Enchantments.FORTUNE` 是 ResourceKey，经注册表转 Holder（与 `BlockHelper.java:250-251` 一致）。

渲染：模组本地 `ExtremeDrillRenderer`（镜像 `DrillRenderer.java:27-30`）+ `OrientedRotatingVisual.of(EXTREME_DRILL_HEAD)`，钻头几何复制自 Create，贴图换成本模组 `extreme_drill/` 占位图。

## B28 终焉水车 `extreme_water_wheel`

沿用 Create 水车（`WaterWheelBlock`/`WaterWheelBlockEntity`）的朝向、形状、材质交互。

**关键应力语义**（以 Create 真源为准）：发电机**总应力 = 基础容量 × 转速**。
- `GeneratingKineticBlockEntity.java:72-76`：`stressTotal = stressBase * speed`。
- `BlockStressValues.java:16-18`：CAPACITIES 是"1RPM 基准容量"。
- Create 水车注册 `setCapacity(32)`、`setGeneratorSpeed(8)`（`AllBlocks.java:580-581`）→ 普通水车总应力 = 32 × 8 = **256 SU**。

本方块覆写：
- **恒 256RPM，无需流体**：`getGeneratedSpeed()` 返回 256（普通水车仅 ±8RPM 且依赖流量）。`initialize()` 启动发电（镜像 `CreativeMotorBlockEntity.java:67-71`）。
- **基础容量 = Create 水车基础值 × 5**（2026-11-20 按用户要求从"与水车一致"上调 5 倍）：`calculateAddedStressCapacity()` 读 `BlockStressValues.getCapacity(AllBlocks.WATER_WHEEL.get())`（默认 32，随 Create 配置联动）再乘 `BASE_CAPACITY_FACTOR = 5` → 160 SU/RPM。转速 256 → 总应力 = 160 × 256 = **40960 SU**，是普通水车的 160 倍。`ModStress` 的 CAPACITIES 静态查询共用同一常量，护目镜/应力表显示一致。
- **有流体应力翻倍**：覆写 `determineAndApplyFlowScore` 拦截父类流量调速，改为检测轮缘偏移（复用父类 `getOffsetsToCheck()`）有无流体；有流体时容量 ×2 → 总应力 = 320 × 256 = **81920 SU**。转速不变。

渲染：**轮体完全模组本地化、固定贴图**（按用户选择）。专属 `ExtremeWaterWheelRenderer` / `ExtremeWaterWheelVisual` 直接使用模组轮体 partial `ModPartialModels.EXTREME_WATER_WHEEL`（`extreme_water_wheel/wheel.json`，OBJ 几何复制自 Create `water_wheel.obj`/`.mtl`，贴图固定指向 `extreme_water_wheel/`），**不做材质重映射**。朝向变换沿用 Create `rotateToFaceVertical`（BER）与 `rotateToFace(rotationAxis())`（Visual）。外壳 blockstate 模型为模组本地手写模型（`extreme_water_wheel/block.json`）。物品模型为手写 OBJ（`item/extreme_water_wheel.json`，复制 `water_wheel_item.obj`）。

> **水车贴图说明**：轮体所有贴图（`waterwheel_metal`/`axis`/`axis_top`/`oak_log`/`oak_planks`/`gearbox`）均已复制进 `extreme_water_wheel/` 并直接驱动渲染，覆盖同名 PNG 即生效。MTL 用 `#axis/#log/#metal/#planks` 等键由模型 JSON 的 textures 解析，OBJ/MTL 无需改路径。
> **已去掉 Create 水车"右键木板换材质"功能**（BE 覆写 `applyMaterialIfValid` 返回 PASS），轮体外观固定。这是完全模组本地化的取舍。

## 注册与接入

方块/物品/BE 独立注册；创造栏"奇点应力"；镐挖标签；掉落表自掉落；中英语言。应力：钻头 IMPACTS=256，水车 CAPACITIES=水车基准×5（惰性 provider）+ RPM 提示 256（惰性 provider，避免构造期急切 `.get()` 触发未绑定值）。

`ExtremeKineticsSelfTest`（开关 `avaritia.extreme_kinetics.selftest=true`，独立目录 `run/verification/extreme-kinetics`，端口 25465）共 **19 条断言全过**：

- 钻头：实体类型、耗能基准 256、时运 16→5 / 32→10 / 256→80 / 8→0 / 512→80(基础截断×5)、配置 2 倍→256RPM→32、恢复默认 5 倍→80、256RPM 破坏速度 25600、端到端近瞬破坏石头并掉落。
- 水车：实体类型、恒 256RPM、Create 水车基础容量默认32、无流体容量=基础×5、无流体总应力=基础×5×256、有流体容量翻倍、有流体总应力=基础×5×2×256、有流体转速仍 256。

自检要点：① 开头清理测试区（世界跨运行持久化，残留水会干扰"无流体"用例）；② 端到端破坏用例临时关闭应力——钻头 256SU/RPM 仍大于单台水车 160SU/RPM 基准容量，真实网络会过载停转（`getSpeed()` 在 `overStressed` 时返回 0，`KineticBlockEntity.java:289-293`），这恰好印证应力数值正确；实际游戏中 1 台钻头约需 2 台终焉水车供电（256/160 向上取整）。
