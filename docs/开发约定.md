# 开发约定（开工前必读）

> 本文件记录用户对本项目立下的硬规则。每次开工先读一遍，改代码前确认没有违反。

## R1 纹理：新内容一律先复制，后人工改

制作新方块/物品/模型时，**优先从相关模组（Create 等）复制已有纹理到本模组资源包**，作为可运行占位；
用户会后期人工替换成自己的美术，**不要**自己去画、不要去改原贴图、不要用纯色/缺失贴图搪塞。

落地要求：

- 复制到 `src/main/resources/assets/avaritia_singularity_stress/textures/block/<主题>/`，文件名用**本模组语义**命名（例如 `warp_tunnel.png` 而不是 `brass_tunnel.png`）；
- 在设计与代码注释里**写清来源**（哪个模组、哪个路径、尺寸），方便日后追溯与替换；
- 复制**不做任何图像处理**（不调色、不裁剪），保持"一眼能看出是占位"；
- 已复制清单记在设计稿的资源章节里（例：`docs/空间折跃隧道-设计稿.md` `12）。

## R2 功能编号

- 功能按 **B1、B2、…** 递增编号，编号是长期契约：代码注释、雪藏标记、设计稿都引用它。
- 新功能先确认编号（下一个可用号见最近一份设计稿），**不要擅自复用**旧编号。
- 已雪藏的功能：代码/注册/配置/lang 一律用 `[Bxx 雪藏]` 前缀注释保留，**不要删除**（恢复时按标记原样放回，注意 `;` 位置）。

## R3 证据纪律（prove-it）

1. **API 不靠记忆**：动 Create / Ponder / NeoForge 的接口前，先查 `allapis/Create-mc1.21.1-dev` 或反编译出的真源，签名/行为以源码为准。
2. **改完必须编译**：`./gradlew compileJava --offline` 必须绿；跑不了的环境要说明原因。
3. **能测就测**：逻辑改动补 GameTest 或服务器验证；只做了编译验证的，要明确说"只验证了编译"。
4. **渲染/观感类不可直接验证**：不假装验过，交给用户实机确认。
5. **同错不犯两次**：踩过的坑写进对应文档（设计稿/排错表），下次开工先读。

## R4 编码风格

- 注释写**中文**，并且写"为什么这么做"而不是"这行在干什么"；引用 Create 内部行为时带上 `文件:行号`。
- 与 Create 的集成点必须写明**依赖的是哪些内部方法**，方便版本升级时回归。
- 新增 config 一律带 `try/catch 回退默认值`（沿用 `WirelessConfig` 的写法）。
- 客户端类不进 common 路径；渲染/界面相关代码放 `init/client` 或对应包。
