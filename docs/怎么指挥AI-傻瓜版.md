# 怎么指挥 AI 干活（傻瓜版 · 一页纸）

> 不需要懂任何术语。**复制下面的话就行。**

---

## 一、万能开头：每次开工前先说这一句

```
按"机械动力附属"的规矩来：先自检，再给我方案和步骤；我确认后你再动手，每步给我一行进度。
```

这一句会自动触发：先跑自检、先给方案、不闷头写代码、每步报进度。

---

## 二、提需求用三句式（任何场景都照抄）

1. **我在哪看到的**：进游戏 / 手里拿着 / 思索（Ponder）里 / 界面里
2. **我看到什么**：黑块 / 不转 / 看不见 / 位置错了 / 图标歪了
3. **我想要什么**：跟某个东西一样 / 别发黑 / 会转 / 能点

**例子（直接改名词即可）**：

```
我在游戏里放了个无线漏斗，它的透明部分是黑块。
我想要它跟旁边的黄铜漏斗一样正常透明。
```

三句话说清，比说"渲染有问题你看着办"有效十倍。

---

## 三、六句现成口令（复制就能用）

| 场景 | 复制这句 |
| --- | --- |
| 加新方块 | `帮我加一个 XX 方块。先告诉我它要动哪几个文件、每个文件放什么地方，我确认后你再写。` |
| 外观不对 | `这个方块看着不对。先别改代码，先告诉我最可能的三个原因，以及你打算怎么一个个排除。` |
| 要动起来 | `我要它像创造马达那样有轴、会转。按机械动力的标准做法来，别自己发明。` |
| 透明/镂空 | `模型里有透明的地方。用脚本查一下是不是漏了透明声明，把结果列给我。` |
| 要交付了 | `改完给我三样：编译结果、截图、改动的文件清单。三样缺一不可。` |
| 卡住了 | `如果 10 分钟内修不好，就停下来告诉我卡在哪，给我两个可选方案，别继续硬试。` |

---

## 四、三条禁语（说了 AI 容易走错路）

| ❌ 别说 | 会发生什么 | ✅ 改说 |
| --- | --- | --- |
| 「你随便怎么实现」 | 它自己发明一套，后面返工 | 「按机械动力的标准做法，先讲方案」 |
| 「让它转起来就行」 | 它可能多画一层，屏幕上叠两层 | 「像创造马达那样只有一层、会转」 |
| 「不用验证，看着对就行」 | 它把"编译通过"当证据交差 | 「编译 + 实机截图，两样都要」 |

---

## 五、验收三问（它说"好了"时，你就问这三句）

1. **你改了哪几个文件？**（要一个列表，指到文件名）
2. **编译过了吗？**（贴 `BUILD SUCCESSFUL` 那一行）
3. **进游戏看过了吗？截图呢？**（没截图 = 没看过）

> 只要第 3 条答不上来，这次就不算做完——不管它说得多有道理。

---

## 六、它跑偏时，补这三句把它拉回来

```
先别写代码，先给我方案和代价。
你验证的是编译还是实机？分清楚。
这个坑登记到排错表了吗？编号多少？
```

---

## 七、听不懂它说的术语时

```
用大白话重说一遍，并给我一个游戏里的例子。
```

---

## 八、你自己的检查清单（一分钟）

- [ ] 我说清了「在哪 + 看到什么 + 想要什么」吗？
- [ ] 它先给了方案，还是直接开始改？
- [ ] 它改完给了「文件清单 + 编译结果 + 截图」三样吗？
- [ ] 没有截图时，我是不是被"应该没问题"糊弄了？
