# B26 炽骨立方合成器

## 用途与边界

注册名为 `avaritia_singularity_stress:blaze_cube_crafter`，是终焉动力合成器的低阶版本。复用已有方块的放置、扳手、盖板、红石启动、单格库存、合成动画、容器返还和输出状态机。

- 允许无尽贪婪 `crafting_table_recipe` 中实际等级为 1、2 的配方，即幽谧工作台与炽骨工作台对应的两档。
- 不允许末地、终焉工作台配方。
- 不参与本模组的 `extreme_kinetic_crafting`、`extreme_kinetic_smithing`，也不参与 `avaritia:extreme_smithing`。
- 炽骨合成器只和炽骨合成器组成箭头配方链、扳手共享库存组；终焉动力合成器与终焉锻造器仍按原有规则互连。正常物流仍可在不同机器之间搬运物品，但不会把两种阵列合并为同一次合成。
- 应力占用沿用现有合成器的 8 SU/RPM，未新增配置或自行指定制造配方。创造栏可直接取得方块。

## 实现入口

`content/blaze_cube_crafter/BlazeCubeCrafterBlock` 与 `BlazeCubeCrafterBlockEntity` 使用独立方块实体类型，继承现有行为。

`ExtremeCrafterHelper.canConnect` 是机器系列兼容性的统一判定，供放置对齐、箭头链正反遍历、扳手库存连接和连接纹理共同使用。组合库存读取时同样过滤不同系列的成员，避免重载后的旧控制器坐标跨系列访问库存。

`ExtremeRecipeGridHandler.tryToApplyRecipe` 在所有动能合成、动能锻造和终焉锻造分支之前处理炽骨机器，仅进入带等级白名单的 Avaritia 工作台匹配。

### 等级依据

以本地依赖 `Re-Avaritia-neoforge-1.21.1-1.4.1-release.jar` 的实际字节码为准，用 `javap -c` 检查以下接口及实现：

- `ITierCraftingRecipe.getTier()` / `hasRequiredTier()`；
- `ShapedTableCraftingRecipe.getTier()`：未显式指定等级时，按宽高推导 1～4 档；
- `ShapelessTableCraftingRecipe.getTier()`：未显式指定等级时，按材料数量推导 1～4 档；
- `TierInput.of(...)`：裁剪输入网格并保留传入等级。

因此筛选实际 `getTier() == 1 || getTier() == 2`，不把 `hasRequiredTier() == false` 当作无条件放行。显式指定为末地/终焉等级的小配方也会被拒绝。

### Create 集成依据

- `allapis/Create-mc1.21.1-dev/.../foundation/block/IBE.java:63-85`：使用 `getBlockEntityType()` 创建实例，按实体类的 `isInstance` 检查，因此子类只需覆写自己的实体类型。
- `allapis/Create-mc1.21.1-dev/.../content/kinetics/crafter/ConnectedInputHandler.java:39-115`：延续侧面扳手交互与控制器合并/拆分算法，只替换机器兼容性边界。
- 渲染复用现有 `ExtremeCrafterRenderer` / `ExtremeCrafterVisual`，分别注入独立资源集合；普通 BER 与 Flywheel 路径均接入。

## 纹理替换

所有占位图均原样复制到 `src/main/resources/assets/avaritia_singularity_stress/textures/block/blaze_cube_crafter/`。不绘制、不调色，也不修改原合成器资源。具体源文件、尺寸和用途见《炽骨立方合成器-纹理清单》。

修改贴图后可重新加载资源；若修改文件名或纹理槽，需要同步模型 provider 和 sprite shift。模型与语言数据由 provider 生成，勿只改 `src/generated/resources` 而遗漏生成器。

## B31 炽骨专属配方类型 `blaze_cube_crafting`（2026-11-20）

炽骨立方合成器的专属子类型；**终焉动力合成器也支持**（配方族子类型），**原版工作台无法合成**（独立 RecipeType 分桶，不在 `minecraft:crafting` 内）。

- 实现：`content/recipes/BlazeCubeCraftingRecipe`（继承原版有序合成，与 `ExtremeKineticCraftingRecipe` 同构，含 `accept_mirrored` 镜像开关）；注册在 `ModExtremeRecipeTypes`（type + serializer 同名 `blaze_cube_crafting`）。
- 匹配：`ExtremeRecipeGridHandler.tryBlazeCubeCrafting`。炽骨分支优先于 Avaritia 前两档回退；终焉分支位于专属动能合成之后、Avaritia 回退之前（同料共存时动能优先）。
- datagen：`ModRecipeProvider.blazeCubeCrafting(...)` builder（仅基建，不产默认配方，与现有约定一致）。
- JSON 形态：

```json
{
  "type": "avaritia_singularity_stress:blaze_cube_crafting",
  "pattern": ["AA", "AA"],
  "key": { "A": {"item": "minecraft:blaze_rod"} },
  "result": {"id": "minecraft:blaze_powder", "count": 4},
  "accept_mirrored": false
}
```

- 终端（B29）自 2026-11-20 扩展轮起纳入该类型：炽骨网络与终焉网络都可自动合成 B31 配方（`supportsAutoCraftFor` + `tryToApplyTerminalRecipe` 的 `matchKineticLike` 共用路径）。
- **Avaritia 四工作台不可合成 B31**（字节码证据）：四档工作台共用 `TierCraftMenu`，其匹配只查 `RecipeManager.getRecipeFor(ModRecipeTypes.CRAFTING_TABLE_RECIPE, …)`；`blaze_cube_crafting` 在独立注册分桶，永远不会被返回。原版工作台只查 `minecraft:crafting`，同理不可做。定位与 `create:mechanical_crafting` 一致：只能用合成器系列合成。

## 验证方法

编译与生成资源：

```bash
./gradlew compileJava --offline
./gradlew runData --offline
```

独立服务端自检：

```bash
./gradlew runServer --offline --init-script gradle/verification/run-blaze-crafter-verify.init.gradle
```

自检仅在显式设置 `avaritia.blaze_cube_crafter.selftest=true` 时运行，使用 `run/verification/blaze-crafter` 独立目录（已备好必需依赖与 EULA，端口 25464，全新世界）。不会读取用户日常游戏世界。自检完成会停止测试服务器，正常启动不受影响。

`BlazeCubeCrafterSelfTest` 共 30 条断言，覆盖：

- 注册：放置炽骨方块得到 `BlazeCubeCrafterBlockEntity`；
- `canConnect` 矩阵：炽骨↔炽骨通，炽骨↔终焉动力/锻造断，终焉动力↔锻造仍通；
- 箭头链与前置链：炽骨→终焉被隔断、炽骨→炽骨连通、终焉动力→锻造仍连通；
- 扳手 `shouldConnect` 与库存组 `toggleConnection`：跨系列拒绝、同系列正常；
- 配方档位（受控注入无序配方）：tier1/2 炽骨接受、tier3/4 炽骨拒绝，终焉动力四档全接受；
- 本模组动能合成：炽骨拒绝、终焉动力接受。
- B31 炽骨专属类型：炽骨接受、终焉动力接受、工作台分桶不可做；两类型同料共存时终焉动力动能优先、炽骨取专属类型。

自检开头清理测试区（世界跨运行持久化，残留 BE 会干扰库存组断言）；init 脚本带 `-Djava.awt.headless=true`（防 Windows 停服后 AWT 非守护线程吊住 JVM，与 terminal 脚本同）。

**已验证结果**：`compileJava --offline` 通过；`runData --offline` 生成 16 变体 blockstate、主体/部件/物品模型、中英文语言、掉落表与镐挖标签；隔离服务端自检 `RESULT 25/25 · DONE ALL PASS`。

**B31 复核（2026-11-20 18:17:12）**：`compileJava`+`runData` 通过；自检 `RESULT 30/30 · DONE ALL PASS`（日志 `/tmp/b31c-blaze.log`）。

实机渲染仍需确认：

1. 放置并驱动炽骨合成器阵列，检查主体、背部齿轮、箭头、盖板、皮带动画和物品动画；分别检查 Flywheel 开启及关闭时的效果。
2. 扳手连接两个炽骨合成器，确认连接纹理及自动输入；贴邻终焉动力合成器和锻造器时不出现跨系列皮带或连接纹理。
3. 实测两档工作台配方，并确认相同材料的高阶配方无法在炽骨阵列启动合成。

构建通过不能替代游戏内渲染检查。
